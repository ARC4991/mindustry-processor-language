# 字符串与输出运行时（讨论稿）

> 状态：字符输出块全局去重已确认；字符串拼接的公开语法与运行时序列存储策略待确认。

## 目标

MPL 的字符串以输出为中心。目标 mlog 的 print 缓冲区会顺序追加输出，因此：

~~~mpl
print("状态：", state, "，血量：", health);
~~~

不需要构造中间字符串，编译器可直接按参数顺序生成输出。printflush 负责将缓冲区交给指定显示目标。

## 全局字符输出表（已确认）

编译器收集整个编译单元中用到的字符。每个字符只生成一个输出处理块：

~~~text
字符“你” → 输出“你”的代码地址
字符“好” → 输出“好”的代码地址
字符“！” → 输出“！”的代码地址
~~~

字符串表不保存字符文本，而是保存这些输出处理块的地址序列：

~~~text
"你好！" → [地址(你), 地址(好), 地址(！)]
"你好"   → [地址(你), 地址(好)]
~~~

输出分发器逐项读取地址，通过宏中间语言的间接跳转进入字符处理块；处理块输出字符后回到分发器。字符输出块全局唯一，因此相同字符不会重复生成代码。

## 拼接

字符串的底层操作可以视为地址数组操作：

~~~mpl
var message: str = prefix + ", " + name;
print(message);
~~~

常量拼接在编译期折叠。直接作为 print 参数的拼接也可拆成连续输出，避免创建中间字符串表。

若拼接结果要存入变量、传给函数或再次参与运算，运行时需要表达新的地址序列。字符输出块仍然复用；需要决议的是新序列采用哪种表示：

| 方案 | 特点 |
| --- | --- |
| 连续数组 | 输出简单；拼接需要复制地址序列与分配连续空间。 |
| 片段/链式序列 | 拼接可复用已有片段；输出需要遍历片段，可能需要额外调度状态。 |
| 固定容量缓冲区 | 资源边界明确；需要指定容量与满缓冲区行为。 |

因此，“字符表不会无限分配”与“运行时拼接结果是否需要序列空间”是两个独立问题。前者已经由全局去重解决；后者仅影响动态、可长期保存的拼接结果。

## 当前边界

- MPL 源码不使用 @；字符串表、地址读取和 @counter 间接跳转发生在宏中间语言及其展开结果中。
- 普通数值、布尔值和游戏对象可直接作为 print 参数输出，不需要先转换为 str。
- str 的相等比较、字符索引、长度、切片、可变修改与内存耗尽行为尚未确定。
- 字符的编码单位、转义规则及对目标 Mindustry 版本的兼容性需要原型验证。
