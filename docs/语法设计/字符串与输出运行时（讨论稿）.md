# 字符串与输出运行时（讨论稿）

> 状态：UTF-16 代码单元输出块全局去重已确认；动态 String 的容量、物理布局与公开拼接语法待冻结。

## 目标

MPL 的字符串以输出为中心。目标 mlog 的 print 缓冲区会顺序追加输出，因此：

~~~mpl
print("状态：", state, "，血量：", health);
~~~

不需要构造中间字符串，编译器可直接按参数顺序生成输出。printflush 负责将缓冲区交给指定显示目标。

## 全局代码单元输出表（已确认）

编译器收集整个编译单元中用到的 UTF-16 代码单元。每个代码单元只生成一个输出处理块：

~~~text
代码单元“你” → 输出“你”的代码地址
代码单元“好” → 输出“好”的代码地址
代码单元“！” → 输出“！”的代码地址
~~~

字符串表不保存字符文本，而是保存这些输出处理块的地址序列：

~~~text
"你好！" → [地址(你), 地址(好), 地址(！)]
"你好"   → [地址(你), 地址(好)]
~~~

输出分发器逐项读取地址，通过宏中间语言的间接跳转进入代码单元输出块；处理块输出后回到分发器。输出块全局唯一，因此相同代码单元不会重复生成代码。

“代码单元”而不是“Unicode 字符”是有意的：v146 的 Message 文本缓冲使用 Java `StringBuilder`，400 的上限也按 UTF-16 长度计算。一个非 BMP 字符可能占两个代码单元，运行时必须保证两个单元在同一次缓冲拼接中按顺序输出。

## 拼接

字符串的底层操作可以视为地址数组操作：

~~~mpl
var message: String = prefix + ", " + name;
print(message);
~~~

常量拼接在编译期折叠。直接作为 print 参数的拼接也可拆成连续输出，避免创建中间字符串表。

若拼接结果要存入变量、传给函数或再次参与运算，运行时需要表达新的地址序列。输出块仍然复用；但 mlog 不能按运行时下标读取处理器变量，因此地址序列不能用“很多虚拟变量”实现。它必须放在编译器管理的物理 Memory 中：

~~~text
String 记录 = {物理起始地址, 长度, 容量}
物理地址 i = 对应代码单元输出块的 mlog 地址
分发器：read 地址 → set @counter 地址 → 输出块 → 返回分发器
~~~

分发器的当前索引、结束地址和返回地址是跨 tick 私有状态；一次动态输出不能重入。它们由链接器从 `memory virtual` 的静态槽预算中分配。

需要决议的是新序列的分配策略：

| 方案 | 特点 |
| --- | --- |
| 连续数组 | 输出简单；拼接需要复制地址序列与分配连续物理空间。 |
| 片段/链式序列 | 拼接可复用已有片段；输出需要遍历片段，可能需要额外调度状态和物理元数据。 |
| 固定容量缓冲区 | 资源边界最明确；需要指定容量与满缓冲区语义。 |

因此，“输出块不会无限分配”与“运行时拼接结果是否需要序列空间”是两个独立问题。前者由全局去重解决；后者仍占用固定的物理容量。为保持“只做编译期失败”的方向，第一版应要求每个动态 String 的最大长度和最大并发数可静态证明；无法证明时构建失败，而不是运行时静默截断或耗尽。

## 当前边界

- MPL 源码不使用 @；字符串表、地址读取和 @counter 间接跳转发生在宏中间语言及其展开结果中。
- 普通数值、Bool 和 profile 明确支持的游戏对象可直接作为 print 参数输出，不需要先转换为 String。
- `Message.print(...)` 自动 flush，但不是原子事务；展开的 `print`、动态分发和 `printflush` 之间可跨 tick。
- 单次 Message 可见输出最多为 400 个 UTF-16 代码单元。常规 `print` 应要求静态最大长度不超过该值；若未来需要明确截断，使用单独的 `printTruncated` API，不能把截断伪装成完整输出。
- String 的相等比较、字符索引、长度、切片、可变修改和固定容量的表面语法尚未确定。
- v159.7 的 `printchar` 可优化单个动态代码单元输出，但不能改变 MPL 的 String 表示、长度上限或拼接语义。
