# 硬件声明、内存与图形接口（讨论稿）

> 状态：硬件声明与 MPL 源码解耦、物理/虚拟内存分层、组合屏幕与 print 自动刷新已确认；声明文件的确切文件名和部分关键词待冻结。

## 硬件声明文件

每个项目有且仅有一个专用硬件声明文件。它不包含业务逻辑，而是将处理器链接的游戏建筑声明为可导出的特殊常量。普通 MPL 模块只依赖这些常量的类型，不直接依赖链接编号，从而与地图硬件解耦。

以下是建议语法：

~~~mpl
// 硬件声明文件（文件名待定）
const TopLeft: Display = link(0);
const TopRight: Display = link(1);
const BottomLeft: Display = link(2);
const BottomRight: Display = link(3);

export const MainScreen: Display = Display.combine([
    [TopLeft, TopRight],
    [BottomLeft, BottomRight]
]);

export const AlertBoard: Message = link(4);
export const Data: Memory = Memory.physical(
    link: 5,
    size: 512
);
export const Runtime: Memory = Memory.virtual(
    size: 4096,
    mode: Pool
);
export const LaunchSwitch: Switch = link(6);
~~~

link(...)、Display.combine(...)、Memory.physical(...) 与 Memory.virtual(...) 仅能在硬件声明文件中使用。这里的 const 是硬件特殊常量：它们在编译期绑定类型、链接位置和容量，不能在普通代码中重新赋值。

## 组合屏幕

Display.combine(...) 接受二维矩阵。2 × 2 的四块屏幕、3 × 3 的九块屏幕等都被视为一个逻辑 Display：

~~~mpl
const MainScreen: Display = Display.combine([
    [Screen0, Screen1, Screen2],
    [Screen3, Screen4, Screen5],
    [Screen6, Screen7, Screen8]
]);

const width: Int = MainScreen.width;
const height: Int = MainScreen.height;
~~~

编译器在编译期验证矩阵为矩形、每格均为兼容屏幕，并从组成屏幕推导 width 和 height。组合 Display 的绘制命令被降级为各物理屏幕的绘制和刷新；因此组合规模会线性增加输出指令数。坐标转换、跨屏幕图元的裁剪及不同规格屏幕混排需要原型验证。

## 物理内存与虚拟内存

### 物理内存

Memory.physical(...) 对应真实链接内存单元或内存库。容量、类型与链接位置都由硬件声明文件在编译期确定：

~~~mpl
Data[0] = oreCount;
var saved = Data[0];
~~~

编译器必须在编译期检查物理内存访问：常量下标不得越界；动态下标只有在范围可证明时才允许。未能证明范围的访问是编译错误，而不是运行时错误。

### 虚拟内存

Memory.virtual(...) 不绑定游戏内存建筑。它由编译器分配为处理器内部变量，是函数局部变量、类字段、字符串表索引和 runtime 元数据的存储基础。它不应被误解为独立的目标虚拟机或额外硬件。

编译器统一命名和分配虚拟内存，防止模块、包、字符串 runtime 与单位 runtime 相互冲突，并在构建报告中显示其使用量。

物理与虚拟内存对业务代码具有同一个 Memory 类型和同一套下标语法：

~~~mpl
Data[0] = oreCount;
Runtime[0] = oreCount;
~~~

二者的差异只影响代码生成。虚拟内存也必须声明 size，以便编译器静态分配变量和对象池。初始管理模式为 Static、Pool 与 Manual：Static 用于固定运行时槽位，Pool 用于 new/delete 对象池，Manual 只允许显式下标使用。

## 图形与文本对象接口

Display 与 Message 是硬件对象。文本输出由 Message 管理并自动刷新：

~~~mpl
AlertBoard.print("敌人数量：", enemyCount);
// 编译器在本次调用结尾自动输出 printflush(AlertBoard)
~~~

Display 提供接近 HTML5 Canvas 的基础绘制接口：

~~~mpl
MainScreen.clear(Color.black);
MainScreen.fill(Color.green);
MainScreen.fillRect(8, 8, 40, 20);
MainScreen.stroke(Color.white);
MainScreen.strokeRect(8, 8, 40, 20);
MainScreen.line(0, 0, MainScreen.width, MainScreen.height);
MainScreen.flush();
~~~

第一版只对目标 draw 指令提供一对一或接近一对一的封装；clear、fill、stroke、矩形、线和 flush 是优先范围。复杂路径、字体、图像、变换栈和保留式画布不在第一版承诺中。

## 资源独占与包

硬件声明的导出常量自动对项目 MPL 代码可见，不需要特别 import。包不能硬编码 link 编号、物理内存地址或组合屏幕布局；包通过 import with {...} 接收调用方传入的硬件常量。若同一资源被多个模块写入，声明文件或构建配置应显式标注其共享/独占策略；编译器至少应给出冲突警告。
