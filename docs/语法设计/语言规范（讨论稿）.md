# MPL 语言规范（讨论稿）

> 状态：讨论中，尚未冻结。本文用于统一语法讨论；只有标为“已确认”的规则，才能作为后续编译器实现的输入约定。

## 1. 定位与原则

MPL（Mindustry Processor Language）是一门高级语言。它先被编译为支持游戏基础宏的宏中间语言，再由后者编译为 Mindustry Logic（以下简称 mlog）处理器指令。MPL 的目标是让玩家能以结构化的方式书写变量、函数和控制流，并以高级对象模型访问游戏能力。

- 输出必须能映射到游戏支持的 mlog 指令与运行时能力。
- 常用流程应比手写跳转更清晰；编译器负责生成标签、跳转和临时变量。
- MPL 源码不出现 @；游戏基础能力只在宏中间语言以 @ 宏暴露。
- 语法与语义分开演进。本文先固定表面语法，类型系统、标准库和内存模型仍可调整。

## 2. 文件、字符集与注释（已确认）

- 源文件扩展名为 .mpl，文本编码为 UTF-8。
- 项目与包的 `src` 目录可同时包含 .mpl 与 .mil 源文件；.mil 的宏规则见《宏中间语言设计（讨论稿）》。当前原型允许 `mpl.json.entry` 指向其中任意一个入口，并支持项目 `src` 内相对路径的具名 import/export、跨 MPL/MIL 链接与依赖初始化。外部 registry 包和锁文件解析仍未实现。两种源码均不能读写或声明 Memory，内存只在各自的 `.mplh` 中以预算形式声明。
- 标识符暂限 ASCII：以字母或下划线开头，后接字母、数字或下划线。
- 空白字符不影响语义；语句以分号 ; 结束。
- 单行注释为 // 至行尾，块注释为 /* 与 */ 之间的内容。

~~~mpl
var retryCount: Int = 0;
retryCount += 1;

/* 这段代码会被编译器忽略。 */
~~~

## 3. 词法元素（已确认）

### 3.1 关键字

| 类别 | 关键字 |
| --- | --- |
| 声明 | var、val、const、fun、class、new、this |
| 模块与访问控制 | import、export、with、public、private |
| 类型 | Int、Float、String、Bool、Void |
| 控制流 | if、else、for、while、do、break、continue、return |
| 布尔字面量 | true、false |
| 空字面量 | null |

关键字不能用作标识符。

### 3.2 字面量与内建符号

~~~mpl
42          // 整数字面量
3.14        // 小数字面量
.5          // 小数字面量
"hello"     // 字符串字面量，支持反斜杠转义
true        // 布尔字面量
null        // 只能赋给可空对象引用
~~~

@ 不是 MPL 的词法元素。它属于宏中间语言，用于访问游戏基础能力；详见《宏中间语言设计（讨论稿）》。

MPL 提供 `Unit` 与 `Building` 两个对象查询命名空间。它们在宏中间语言中映射到目标游戏内容，但不占用目标程序变量；首批 API 是 `Unit.getAll类型()` 与 `Building.getAll类型()`，用于构造可迭代查询对象。

## 4. 声明与类型

### 4.1 变量、常量与作用域（已确认）

~~~mpl
var health: Int = 100;
val name: String = "core";
const val maxRetries: Int = 3;
~~~

| 形式 | 意图 | 规则 |
| --- | --- | --- |
| var | 可重新赋值的变量 | 必须在声明时初始化；可位于顶层或代码块内 |
| val | 初始化后不可重新赋值的运行时值 | 必须在声明时初始化；可位于顶层或代码块内 |
| const val | 编译期常量，初始化式须可在编译期求值 | 可用于常量表达式、类型数组长度和包资源参数 |

类型标注可省略，编译器从初始化表达式推导类型：

~~~mpl
var counter = 0;
val enabled = true;
~~~

未提供类型也没有初始化式的声明不允许，也不存在“零值初始化”。块级声明遮蔽外层同名变量时，必须显式写出新的 `var` / `val`；同一作用域内重名是错误。函数可读取顶层变量，但编译器必须证明每条到达调用点的控制路径都已完成该变量初始化；不能依赖目标处理器的残留变量值。

### 4.2 内建类型（讨论基线）

| 类型 | 用途 |
| --- | --- |
| Int | 数组下标、位运算与整数计数；目标层以数值保存，但不暴露游戏的 `flag` |
| Float | 坐标、距离、生命值、速度、时间与一般小数运算；映射到目标层 double 数值 |
| String | 由字符串运行时管理的文本值 |
| Bool | true / false 条件值；目标层以数值表达，但不能当作 Int 或 Float 使用 |
| Void | 无返回值函数的返回类型；不能作为变量或字段类型 |

Int、Float、String、Bool、Void 是语言层内建类型。类型名必须使用大驼峰；游戏对象、内容类型和链接建筑等同样使用大驼峰类型名。

### 4.3 可空对象（已确认）

MPL 默认引用不可空。只有对象引用类型可在类型名后加 `?`，例如 `Unit<Dagger>?`、`Building<Duo>?`；`Int?`、`Float?`、`Bool?` 不存在。`null` 只能赋给可空对象类型，且 `val value = null` 因缺少具体对象类型而是编译错误。当前编译器已实现 `Unit<T>?` 与 `null`；其他可空对象类型仍待对应对象 Runtime 落地。

~~~mpl
val target: Unit<Dagger>? = Unit.getAllDagger().get(0);
if (target != null) {
    target.move(40.0, 20.0);
}
~~~

`if (value != null)` 的真分支会将稳定的 `val` 流缩窄为非空类型；`if (value == null) ... else ...` 的 else 分支同理。离开该分支后缩窄失效；当前编译器不收窄 `var`。非空成员访问和方法调用绝不自动解包可空值。

安全调用与默认值保留为后续语法：未来 `target?.health` 的类型为 `Float?`，而 `target ?: fallback` 要求两侧为同一对象类型并得到非空对象；当前 ANTLR 文法尚不接受这两个运算符。`!!` 不存在，MPL 不提供“相信我、不检查 null”的运行时崩溃入口。来自 `.mplh` 的链接常量是非空声明；动态 radar、locate、sensor 等观察结果未来也可为 null。

### 4.4 数值运算（已确认）

- 不含小数点的数值字面量是 Int；含小数点的字面量是 Float。
- Int 与 Float 在算术和比较中允许 Int 向 Float 的安全提升；Float 不会隐式转换为 Int。
- Int / Int 的结果是 Float；位运算和数组下标只接受 Int。
- 对象、String、Bool 与数值之间不存在隐式转换。转换必须通过显式标准库 API 完成。
- Bool 只由 Bool 表达式产生；`&&` 与 `||` 保证短路，不把目标 mlog 的数值真值规则暴露给源码。

~~~mpl
var count: Int = 3;
var distance: Float = count + 0.5;
var half: Float = count / 2;
var index: Int = Int.floor(distance);
~~~

MPL 不直接继承 mlog 的数值/对象混用规则。为了让任何 `Int` 都能准确存入目标的 `double`，`Int` 定义为有符号 32 位整数，范围为 `-2_147_483_648..2_147_483_647`。这也让数组长度、地址、Unit runtime tag 与多处理器通信字段有统一且可验证的表示。

`Int` 的 `+`、`-`、`*` 是**饱和算术**：结果超出范围时分别取 `Int.max` 或 `Int.min`；常量表达式同样按此规则求值。`/` 的结果始终为 `Float`。`Int % Int` 使用“商向零截断”的余数定义，余数与左操作数同号；右操作数为 `0` 时结果为 `0`。位运算先把操作数规范为 32 位二进制补码，结果再解释为有符号 32 位整数；移位量按 `amount & 31` 处理，`>>` 为算术右移。

`Float` 是有限的 IEEE-754 double 值：字面量、变量与外部读取均不得把 `NaN` 或正负无穷作为 MPL 值。所有浮点运算是全定义的：除数为 `0.0` 时结果为 `0.0`；其余产生非有限结果时，正/负溢出分别饱和到 `Float.max` / `-Float.max`，未定义的结果（例如 `0.0 / 0.0`）规范为 `0.0`。比较操作不会接触 NaN，故满足通常的全序比较。profile lowering 必须在目标层产生 null 前完成这些保护；不能把 null、NaN 或 Infinity 泄漏回 MPL。

当前实现已在常量优化中执行 Int 字面量、加减乘和零除余数的饱和/归一化；对非恒定 `Int` 的加、减、乘，v146 lowering 在运算后以 `min` / `max` 夹紧至 32 位范围，并为 `%` 生成除数为零时直接返回 `0` 的分支。对 `Float`，常量求值会拒绝非有限字面量，并将零除、NaN 和正负溢出归一为规范值；非恒定加减、乘除在目标 `op` 前比较安全边界，除数为零时直接写入 `0.0`，否则只在结果可表示时才执行运算。两类序列都不依赖游戏把 NaN 或 Infinity 静默改写为零。

显式转换仅提供 `Int.floor(Float)`、`Int.ceil(Float)` 与 `Int.round(Float)`：输入先按 Float 规则规范，再饱和到 Int 范围。不存在 Bool、String、对象与数值之间的隐式或显式强制转换。

### 4.5 时间（已实现的首批内建 API）

时间 API 统一位于 `Clock` 命名空间，均为只读属性而不是可写变量。MPL 不直接暴露 mlog 的 `@time` 名称或单位。

| MPL 属性 | 类型 | 含义与 v146 lowering |
| --- | --- | --- |
| `Clock.timeMs` | `Float` | 自游戏时间起算的毫秒数，直接读取 v146 `@time` |
| `Clock.time` | `Float` | 秒，等价于 `Clock.timeMs / 1000.0` |
| `Clock.timeMinutes` | `Float` | 分钟，等价于 `Clock.timeMs / 60000.0` |
| `Clock.timeHours` | `Float` | 小时，等价于 `Clock.timeMs / 3600000.0` |
| `Clock.tick` | `Float` | 游戏 tick 数，直接读取 v146 `@tick`；游戏的 delta 可使其带小数 |

例如，以每秒 20 度的速度旋转应写成：

~~~mpl
val angle: Float = Clock.time * 20.0;
~~~

`Clock.timeMs` 特意保留毫秒后缀，避免把源 mlog 的单位误读为秒。`Clock.tick` 也保留目标层的精确 `Float`，MPL 不会隐式截断它；需要整数离散 tick 时使用 `Int.floor(Clock.tick)`、`Int.ceil(...)` 或 `Int.round(...)`。时间值依赖游戏的时间推进；它不是 wall-clock 日期时间，也不是一个跨处理器同步原语。

### 4.6 失败、部署与目标世界（已确认）

MPL 不实现异常、panic、`Result` 或用户可捕获的运行时失败。每一种失败必须属于下表之一：

| 情况 | MPL 语义 |
| --- | --- |
| 语法、类型、可空性、资源预算、未满足 profile 能力 | 构建期错误，不产生 mlog |
| 可静态发现的硬件类型/alias、Memory 容量、外部包需求不匹配 | 构建期错误 |
| 蓝图外硬件在实际地图中被拆除、重连、超出范围或不同队 | 部署期契约失败；`mpl hardware check` 报错，程序不承诺业务效果 |
| 动态查询没有结果 | 返回可空对象或空 Set，不是错误 |
| Unit/Building 已消失、玩家接管 Unit、游戏拒绝控制 | 目标世界状态；读取得到 profile 定义的默认/可空结果，控制命令无效果 |
| 算术异常、String/对象容量不足 | 按本规范的总定义或静态容量证明处理，不产生目标层 runtime error |

生成代码可以因 IPT 在任意 mlog 指令后跨 tick 继续，但这只影响完成时刻，不把一个已通过类型和资源检查的 MPL 程序变成可捕获失败。

### 4.7 聚合类型（静态第一版已实现）

~~~mpl
val point: (Float, Float) = (12.0, 34.0);
var queue: Int[] = [1, 2, 3];
val active = listOf(1, 2, 3);
val allowed = setOf(1, 3, 5);
~~~

- `(T1, T2, ...)` 表示元组类型；元组值用相同的圆括号形式书写，且至少有两个元素。
- `T[]` 表示元素类型为 T 的数组；长度由初始化字面量决定，不属于公开类型身份。`T[N]` 不是 MPL 语法。
- 数组字面量以方括号书写，元素以逗号分隔。`List<T>` / `Set<T>` 分别通过 `listOf(...)`、`List.of(...)` 和 `setOf(...)`、`Set.of(...)` 创建。
- 元组、数组、List、Set 支持常量下标读取、`size` 与 `for (var item : values)`。数组、List、Set 支持 `contains(value)`；只有 `var` 数组支持 `set(index, value)`。

常量下标聚合使用编译器私有的处理器变量槽。对 `Int`/`Float`/`Bool` Array，编译器还可证明 `for (var i = 0; i < array.size; i += 1)` 中的 `array[i]` 和 `array.set(i, value)`，并自动改用物理 Memory。其他动态下标、嵌套聚合、整体复制/重新赋值、聚合函数传参与返回、可变 List/Set 仍未实现。详细规则见《聚合类型与静态容器（讨论稿）》与《动态聚合 Memory 运行时（讨论稿）》。

## 5. 函数与调用（基础语法与静态 ABI 已实现）

~~~mpl
fun clamp(value: Float, lower: Float, upper: Float): Float {
    if (value < lower) {
        return lower;
    }
    if (value > upper) {
        return upper;
    }
    return value;
}

var result = clamp(8, 0, 5);
~~~

- 函数由 fun 声明，参数必须带类型标注。
- 返回类型位于右括号后的 : 之后；省略时表示 `Void`。
- return; 可用于无返回值函数；return expression; 用于有返回值函数。
- 第一版函数采用静态、不可重入 ABI，调用图不得有环；直接和间接递归均为编译错误。
- 实参从左到右求值；函数参数、局部变量、返回值和返回地址由编译器分配内部槽，`return` 通过内部 `@counter` 跳转完成。
- 函数声明会预注册，因此普通函数可前向调用；函数只能访问在其声明前已声明的顶层变量。
- 顶层变量按源码顺序初始化。编译器沿调用图传递函数的全局依赖，并拒绝在任一直接或间接依赖尚未初始化时发生的顶层调用；变量自己的初始化表达式也不能经函数回读该变量。
- 第一版函数体不能开启 Unit Set 遍历、读取其 `size/get`、访问已保存 UnitRef，也不能捕获或保存遍历过程中借用的 `Unit`；UnitRef 参数和返回类型同样被拒绝。这项限制会在函数调用能够保存并恢复唯一 `@unit` 上下文后重新评估。

游戏功能的高级 API 会以普通 MPL 调用形式提供；其具体集合尚待设计。它们在第一编译阶段被降级为宏中间语言的 @ 宏，而不是直接出现在 MPL 源码中。

## 6. 语句与控制流（基础结构化控制流已实现）

~~~mpl
if (oreCount > 0) {
    mineOre(oreX, oreY);
} else if (enemyNear) {
    defend();
} else {
    waitForWork();
}

for (var i: Int = 0; i < 10; i += 1) {
    tick(i);
}

while (enabled) {
    tick();
}

do {
    retry();
} while (failed);
~~~

当前编译器已经实现 `if` / `else if` / `else`、`while`、`do-while`、三段式计数 `for` 和 UnitSet 遍历。条件必须是 `Bool`。计数 `for` 的初始化、条件和更新均可省略；省略条件等价于 `true`，声明式初始化变量只在该 for 内可见。`break` 跳到最近一层循环的结束位置；`continue` 在计数 for 中先执行更新，在 while 中进入下一次条件检查，在 Unit 遍历中推进到下一候选。循环外使用两者是编译错误。

### 6.1 单位与建筑遍历（已确认表面语法）

~~~mpl
for (var unit : Unit.getAllAlpha()) {
    unit.move(100, 80);

    if (unit.health < 30) {
        unit.stop();
    }
}

for (var turret : Building.getAllDuo()) {
    turret.shoot(targetX, targetY, true);
}
~~~

- `Unit.getAllAlpha()` 返回惰性、不可变 `Set<Unit<Alpha>>`；Alpha 是目标 profile 中的单位类型。它可保存为 `val` 并重复遍历。`Building.getAllDuo()` 同理返回 `LinkedBuildingSet<Duo>`，它只遍历 `.mplh` 已声明且类型为 Duo 的链接建筑，绝不代表全地图同类建筑。
- 当控制循环只需要有限编队时，可在全部 `.where(...)` 之后调用 `set.take(n)`；它稳定私有认领至多 n 个单位，而不是按本轮 `ubind` 顺序临时截断。`flag`、owner token 和认领过程仍完全属于编译器 runtime。
- `set.size` 返回当前扫描结果的 `Int`；`set.get(index)` 返回可保存的 `Unit<Alpha>?`，负数或越界为 null。普通查询每次执行弱一致扫描；带 `take(n)` 的查询先同步同一个稳定私有成员集合，再计数或按本次扫描顺序索引。两者都不是数组快照，index 也不是单位身份。
- for 中的 unit 是当前轮的 `Unit<Alpha>`，可直接调用其方法；循环变量逃逸尚未实现。由 `get(...)` 得到的 UnitRef 可在判空后的顶层逻辑中跨 tick 保存和操作；当前不能作为函数参数/返回值、对象字段、跨 shard 值，也不能在另一个 Unit 遍历体中重绑。
- unit 的控制方法直接作用于当前遍历到的单位；建筑控制只对 profile 明确支持的链接建筑能力开放。游戏在该时刻拒绝控制时按目标层行为不生效，不产生 MPL 运行时异常。循环内的 break 与 continue 保持普通循环语义。
- Unit Set/LinkedBuildingSet 可保存为 `val` 并重复用于 `for`，但它们不是数组、不能构造快照、存入字段或跨包导出。同一个受管 Unit Set 的 `size`、`get(index)` 与 `for` 共用一个编译器私有身份；分别使用它们不会认领三批不同单位。
- `LinkedBuildingSet<T>.size/get(index)` 在每次读取时按 `.mplh` 声明顺序展开同类型链接并重新执行过滤；`get` 返回 `Building<T>?`。稳定 `val` 判空后可读字段和调用 profile 授权的控制方法。它不使用 `getlink` 数字、不扫描地图，也不需要 Unit flag runtime。
- 未找到可遍历对象时，循环体执行 0 次；遍历顺序和遍历期间新生成/销毁对象的处理不作保证。

Unit Set 是弱一致遍历：第一版禁止任何 Unit 迭代嵌套，且控制单位可能被其它处理器抢占。用户只使用 `Unit.getAll类型()`、`.where(...)`、`.take(n)`、`size`、`get(...)` 与 Unit 对象；不存在公开的 UnitManager、UnitPool、slot、flag、`manage()` 或 `service()` API。编译器可在底层以 `ubind`、UnitRef 与隐藏 flag 完成单位识别，但当前不会在重新部署后恢复普通 `get(...)` 句柄。详见《单位遍历与私有运行时（讨论稿）》。

### 6.2 遍历过滤 lambda（已确认适用范围）

~~~mpl
for (var unit : Unit.getAllAlpha(unit => unit.health < healthLimit)) {
    unit.move(targetX, targetY);
}

for (var unit : Unit.getAllAlpha(_.health < healthLimit)) {
    unit.move(targetX, targetY);
}
~~~

以下写法等价，并允许先保存查询：

~~~mpl
val damaged = Unit.getAllAlpha().where(unit => unit.health < healthLimit);
for (var unit : damaged) {
    unit.move(targetX, targetY);
}
~~~

`.where(...)` 可连续调用；每个谓词都在前一个 UnitSet 上继续筛选，等价于按书写顺序短路的逻辑 AND：

~~~mpl
val repairable = Unit.getAllAlpha()
    .where(_.health < 50.0)
    .where(_.ammo > 0.0);
~~~

`_` 是单参数 lambda 的简写。第一版 lambda 只可作为 `getAll类型(...)` 或 `.where(...)` 的过滤谓词：它在遍历时内联执行，不可赋给变量、不可返回、不可保存，也不构成通用高阶函数系统。lambda 只可只读捕获外层标量，且不能控制单位、进行 I/O、赋值、`new` 或开启嵌套遍历。

## 7. 表达式与优先级（讨论基线）

从高到低的优先级如下。同一行除特别说明外按左结合处理。

| 优先级 | 形式 |
| --- | --- |
| 最高 | 分组 (expr)、调用 f(...)、下标 a[i]、属性 a.name、方法调用 a.name(...)、安全访问 a?.name |
| 一元 | !、~、+、-、前置 ++、前置 -- |
| 后缀 | 后置 ++、后置 -- |
| 乘法 | *、/、% |
| 加法 | +、- |
| 移位 | <<、>> |
| 比较 | <、>、<=、>= |
| 相等 | ===、!==（对象身份）、==、!=（值相等） |
| 位运算 | &、^、| |
| 逻辑 | &&、|| |
| 条件 | condition ? whenTrue : whenFalse |
| 最低 | =、+=、-=、*=、/=、%=、&=、|=、^=、<<=、>>= |

赋值与条件表达式按右结合处理。对象身份比较、通用属性/方法调用来自 v2 demo，尚未成为第一版承诺；Unit.getAll类型()、Building.getAll类型() 与 profile 明确提供的对象 API 是已确认的例外。

## 8. 暂定 EBNF

下列 EBNF 描述讨论基线，省略空白和注释规则：

~~~ebnf
程序          = { 导入声明 }, { 顶层声明 | 语句 }, EOF ;
导入声明      = "import", "{", 标识符, { ",", 标识符 }, "}", "from", 字符串,
                [ "with", "{", 资源实参, { ",", 资源实参 }, "}" ], ";" ;
资源实参      = 标识符, ":", 标识符 ;
顶层声明      = [ "export" ], ( 函数声明 | 类声明 | 常量声明 ) ;
函数声明      = "fun", 标识符, "(", [ 参数, { ",", 参数 } ], ")",
                [ ":", 类型 ], 代码块 ;
类声明        = "class", 标识符, "{", { 字段声明 | 方法声明 }, "}" ;
字段声明      = [ "public" | "private" ], 标识符, ":", 类型, ";" ;
方法声明      = [ "public" | "private" ], 函数声明 ;
常量声明      = "val", 标识符, [ ":", 类型 ], "=", 表达式, ";" ;
参数          = 标识符, ":", 类型 ;
语句          = 表达式, ";"
              | ( "var" | "val" ), 模式, [ ":", 类型 ], "=", 表达式, ";"
              | 常量声明
              | if语句 | for语句 | 单位遍历语句 | while语句 | doWhile语句
              | "break", ";" | "continue", ";" | "return", [ 表达式 ], ";"
              | 代码块 ;
代码块        = "{", { 语句 }, "}" ;
模式          = 标识符 | "(", 标识符, ",", 标识符, { ",", 标识符 }, ")" ;
类型          = 非空类型, [ "?" ] ;
非空类型      = 基础类型 | 命名类型, [ "<", 类型, { ",", 类型 }, ">" ]
                | "(", 类型, ",", 类型, { ",", 类型 }, ")" | 类型, "[", [ 整数 ], "]" ;
基础类型      = "Int" | "Float" | "String" | "Bool" | "Void" ;
命名类型      = 标识符 ;
if语句        = "if", "(", 表达式, ")", 代码块,
                { "else", "if", "(", 表达式, ")", 代码块 }, [ "else", 代码块 ] ;
for语句       = "for", "(", ( 声明语句 | 表达式语句 | ";" ),
                [ 表达式 ], ";", [ 表达式 ], ")", 代码块 ;
单位遍历语句  = "for", "(", "var", 标识符, ":", 对象遍历, ")", 代码块 ;
对象遍历      = 对象查询 | 标识符 ;
对象查询      = 单位查询 | 建筑查询 ;
单位查询      = "Unit", ".", "getAll", 类型名, "(", [ 过滤lambda ], ")", { ".where", "(", 过滤lambda, ")" }, [ ".take", "(", 正Int字面量, ")" ] ;
建筑查询      = "Building", ".", "getAll", 类型名, "(", [ 过滤lambda ], ")", { ".where", "(", 过滤lambda, ")" } ;
过滤lambda    = 标识符, "=>", 表达式 | "_", 表达式 ;
类型名        = 标识符 ;
while语句     = "while", "(", 表达式, ")", 代码块 ;
doWhile语句   = "do", 代码块, "while", "(", 表达式, ")", ";" ;
~~~

表达式的完整产生式以第 7 节的优先级表为准；其中 `new 类型名(实参)` 为对象分配表达式，`this` 只可出现在实例方法或构造函数内，顶层 `return` 为语义错误。正式语法冻结时会补充拆分的 ANTLR `MplLexer.g4` 与 `MplParser.g4`，并以其作为可执行规范。

## 9. 与 mlog 的映射边界

MPL 不是独立虚拟机。变量赋值、算术、条件分支与高级运行时会先降级为宏中间语言；宏展开后才生成 set、op、jump 等 mlog 指令。函数调用、数组、元组、单位 runtime 与字符串表可能需要展开成标签、临时变量或内存单元。

因此，以下事项必须在实现前确定：

1. 变量、数组和递归调用如何在处理器有限的变量与内存中布局；
2. 函数参数、返回值和嵌套调用如何保存；
3. String 的字符串表、拼接与内存布局；
4. 宏中间语言的宏表如何跟随 Mindustry 版本更新；
5. 优化器能否在不改变游戏行为的前提下折叠常量和删除不可达代码。
