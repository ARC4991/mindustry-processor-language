# MPL 语言规范（讨论稿）

> 状态：讨论中，尚未冻结。本文用于统一语法讨论；只有标为“已确认”的规则，才能作为后续编译器实现的输入约定。

## 1. 定位与原则

MPL（Mindustry Processor Language）是一门编译为 Mindustry Logic（以下简称 mlog）处理器指令的高级语言。它的目标是让玩家能以结构化的方式书写变量、函数和控制流，同时保留对游戏内置对象、单位控制和建筑控制的直接访问能力。

- 输出必须能映射到游戏支持的 mlog 指令与运行时能力。
- 常用流程应比手写跳转更清晰；编译器负责生成标签、跳转和临时变量。
- 语言核心保持小；复杂的游戏能力优先通过 @ 前缀的内建符号暴露。
- 语法与语义分开演进。本文先固定表面语法，类型系统、标准库和内存模型仍可调整。

## 2. 文件、字符集与注释（已确认）

- 源文件扩展名为 .mpl，文本编码为 UTF-8。
- 标识符暂限 ASCII：以字母或下划线开头，后接字母、数字或下划线。
- 空白字符不影响语义；语句以分号 ; 结束。
- 单行注释为 // 至行尾，块注释为 /* 与 */ 之间的内容。

~~~mpl
// 绑定单位并移动
@bindUnit(@flare);
@move(100, 80);

/* 这段代码会被编译器忽略。 */
~~~

## 3. 词法元素（已确认）

### 3.1 关键字

| 类别 | 关键字 |
| --- | --- |
| 声明 | var、val、const、fun |
| 类型 | num、str、bool |
| 控制流 | if、else、for、while、do、break、continue、return |
| 布尔字面量 | true、false |

关键字不能用作标识符。

### 3.2 字面量与内建符号

~~~mpl
42          // 整数字面量
3.14        // 小数字面量
.5          // 小数字面量
"hello"     // 字符串字面量，支持反斜杠转义
true        // 布尔字面量
@unit       // 内建符号
~~~

内建符号以 @ 开头，例如游戏字面量 @flare、@copper，以及编译器提供的内建函数 @bindUnit(...)。可用的符号集合与其参数语义不在本文固定，后续以独立的内建 API 文档维护。

单位类型还可由编译器提供只读的类型对象，例如 Alpha 对应游戏内容 @alpha。类型对象不占用目标程序变量，只能调用编译器明确支持的静态 API；首个已确认 API 是 Alpha.getAll()，用于单位遍历。

## 4. 声明与类型

### 4.1 变量与常量（讨论基线）

~~~mpl
var health: num = 100;
val name: str = "core";
const val maxRetries: num = 3;
~~~

| 形式 | 意图 | 尚待确认 |
| --- | --- | --- |
| var | 可重新赋值的变量 | 是否允许未初始化声明 |
| val | 初始化后不可重新赋值的运行时值 | 是否允许全局 val |
| const val | 编译期常量，初始化式须可在编译期求值 | 是否保留 const 与 val 两个词 |

类型标注可省略，编译器从初始化表达式推导类型：

~~~mpl
var counter = 0;
val enabled = true;
~~~

未提供类型也没有初始化式的声明目前不允许；若需要支持，应在内存模型与默认值规则确定后再加入。

### 4.2 内建类型（讨论基线）

| 类型 | 用途 |
| --- | --- |
| num | mlog 数值、布尔条件和可表示为数值的游戏值 |
| str | 文本与目标平台支持的字符串值 |
| bool | true / false 条件值 |

num、str、bool 是语言层类型。游戏对象、内容类型和链接建筑等是否形成独立类型，暂不在本轮语法中决定。

### 4.3 聚合类型（讨论基线）

~~~mpl
var point: (num, num) = (12, 34);
var queue: num[10] = [1, 2, 3];
var dynamic: str[] = ["a", "b"];
~~~

- (T1, T2, ...) 表示元组类型；元组值用相同的圆括号形式书写。
- T[N] 表示长度为 N 的数组类型；T[] 表示长度尚未在类型中指定的数组。
- 数组字面量以方括号书写，元素以逗号分隔。

数组的存储位置、越界行为、动态长度和元组拆箱的代码生成尚未确定；这些形式先作为语法预留，不能承诺已可编译到 mlog。

## 5. 函数与调用（讨论基线）

~~~mpl
fun clamp(value: num, lower: num, upper: num): num {
    if (value < lower) {
        return lower;
    }
    if (value > upper) {
        return upper;
    }
    return value;
}

var result = clamp(8, 0, 5);
~~~

- 函数由 fun 声明，参数必须带类型标注。
- 返回类型位于右括号后的 : 之后；省略时表示无返回值（暂定）。
- return; 可用于无返回值函数；return expression; 用于有返回值函数。
- 递归、函数是否可在声明前调用、参数默认值以及调用约定都待目标代码生成设计确认。

内建函数同样使用调用语法：

~~~mpl
@bindUnit(@flare);
@move(100, 80);
@shootAt(targetX, targetY, true);
~~~

## 6. 语句与控制流（已确认语法，语义待实现）

~~~mpl
if (oreCount > 0) {
    @mine(oreX, oreY);
} else if (enemyNear) {
    @shootAt(enemyX, enemyY, true);
} else {
    @idle();
}

for (var i: num = 0; i < 10; i += 1) {
    @move(i * 8, 0);
}

while (enabled) {
    tick();
}

do {
    retry();
} while (failed);
~~~

代码块使用 { ... }。break; 只能离开最近的循环，continue; 只能进入最近循环的下一次迭代；这两条约束将在语义分析阶段检查。

### 6.1 单位遍历（已确认表面语法）

~~~mpl
for (var unit : Alpha.getAll()) {
    unit.move(100, 80);

    if (unit.health < 30) {
        unit.stop();
    }
}
~~~

- Alpha 是单位类型对象，getAll() 表示该类型当前可遍历的单位序列。
- unit 是只在循环体中有效的借用 Unit；它不能被返回、存入变量或传出循环体。
- unit 的控制方法作用于当前遍历到的单位；循环内的 break 与 continue 保持普通循环语义。
- getAll() 第一版只允许作为单位遍历的右侧表达式，不构造可存储数组或列表。
- 未找到可遍历单位时，循环体执行 0 次；遍历顺序和遍历期间新生成/销毁单位的处理不作保证。

单位遍历的私有 flag runtime、嵌套遍历限制及低层映射见《单位遍历与私有运行时（讨论稿）》。

## 7. 表达式与优先级（讨论基线）

从高到低的优先级如下。同一行除特别说明外按左结合处理。

| 优先级 | 形式 |
| --- | --- |
| 最高 | 分组 (expr)、调用 f(...)、下标 a[i]、属性 a.name、方法调用 a.name(...) |
| 一元 | !、~、+、-、前置 ++、前置 -- |
| 后缀 | 后置 ++、后置 -- |
| 乘法 | *、/、% |
| 加法 | +、- |
| 移位 | <<、>> |
| 比较 | <、>、<=、>= |
| 相等 | ==、!=、===、!== |
| 位运算 | &、^、| |
| 逻辑 | &&、|| |
| 条件 | condition ? whenTrue : whenFalse |
| 最低 | =、+=、-=、*=、/=、%=、&=、|=、^=、<<=、>>= |

赋值与条件表达式按右结合处理。===、!== 与通用属性/方法调用来自 v2 demo，是否保留取决于游戏对象模型的设计；Alpha.getAll() 与单位遍历变量上的受支持 API 是已确认的例外。

## 8. 暂定 EBNF

下列 EBNF 描述讨论基线，省略空白和注释规则：

~~~ebnf
程序          = { 语句 | 函数声明 }, EOF ;
函数声明      = "fun", 标识符, "(", [ 参数, { ",", 参数 } ], ")",
                [ ":", 类型 ], 代码块 ;
参数          = 标识符, ":", 类型, [ "=", 表达式 ] ;
语句          = 表达式, ";"
              | ( "var" | "val" ), 模式, [ ":", 类型 ], "=", 表达式, ";"
              | "const", "val", 标识符, [ ":", 类型 ], "=", 表达式, ";"
              | if语句 | for语句 | 单位遍历语句 | while语句 | doWhile语句
              | "break", ";" | "continue", ";" | "return", [ 表达式 ], ";"
              | 代码块 ;
代码块        = "{", { 语句 }, "}" ;
模式          = 标识符 | "(", 标识符, ",", 标识符, { ",", 标识符 }, ")" ;
类型          = 基础类型 | "(", 类型, ",", 类型, { ",", 类型 }, ")" | 类型, "[", [ 整数 ], "]" ;
基础类型      = "num" | "str" | "bool" ;
if语句        = "if", "(", 表达式, ")", 代码块,
                { "else", "if", "(", 表达式, ")", 代码块 }, [ "else", 代码块 ] ;
for语句       = "for", "(", ( 声明语句 | 表达式语句 | ";" ),
                [ 表达式 ], ";", [ 表达式 ], ")", 代码块 ;
单位遍历语句  = "for", "(", "var", 标识符, ":", 单位类型, ".", "getAll", "(", ")", ")", 代码块 ;
单位类型      = 标识符 ;
while语句     = "while", "(", 表达式, ")", 代码块 ;
doWhile语句   = "do", 代码块, "while", "(", 表达式, ")", ";" ;
~~~

表达式的完整产生式以第 7 节的优先级表为准；正式语法冻结时会补充 ANTLR 文法并以其作为可执行规范。

## 9. 与 mlog 的映射边界

MPL 不是独立虚拟机。变量赋值、算术和条件分支可直接降级为 set、op、jump 等 mlog 指令；内建函数通常降级为单位控制、建筑控制、内存读写等对应指令。函数调用、数组和元组则可能需要展开成标签、临时变量或内存单元。

因此，以下事项必须在实现前确定：

1. 变量、数组和递归调用如何在处理器有限的变量与内存中布局；
2. 函数参数、返回值和嵌套调用如何保存；
3. str 与游戏对象值在各版本 Mindustry 中的可用范围；
4. 内建符号表如何跟随 Mindustry 版本更新；
5. 优化器能否在不改变游戏行为的前提下折叠常量和删除不可达代码。
