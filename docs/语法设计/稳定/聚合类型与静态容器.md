# 聚合类型与静态容器

> 状态：表面语法、静态 lowering 和 `MutableList<T>` 的容量化 Runtime 已实现；定长 Array 与 MutableList 在标准计数循环中的受证明动态下标已接入物理 Memory runtime。顶层函数及对象方法已支持 `Int`、`Float`、`Bool` 元组与固定形状数组的参数、返回和返回类型推导；嵌套聚合和可变 Set 仍未实现。

## 目标

MPL 不把 mlog 的单个变量伪装成任意对象。第一版元组、数组、List 和 Set 都是**编译期已知长度**的聚合值：编译器为每一个元素分配私有处理器变量槽，并在构建期检查下标和资源消耗。

这使常见的常量配置、坐标、有限任务表和受容量约束的动态列表可直接编译，同时不会把物理 Memory 读写暴露给 MPL/MIL 用户。

## 类型与字面量

### 元组

元组是定长、可异构、按位置访问的值。类型和值都使用圆括号，至少有两个元素：

~~~mpl
val test: (Int, Int, Int) = (1, 2, 3);
val spawn: (Float, Float, Bool) = (24.0, 48.0, true);

val x: Int = spawn[0];
val enabled: Bool = spawn[2];
~~~

元组没有单元素形式，`(value)` 始终只是分组表达式。元组元素不可修改，元组也不能整体重新赋值。

由 `Int`、`Float`、`Bool` 组成的元组可以作为顶层函数参数和返回值。参数按位置传入编译器私有 ABI 槽；返回类型省略时，编译器从每条 `return` 逐位置推导公共类型，`Int` 与 `Float` 会提升为 `Float`：

~~~mpl
fun rotate(source: (Int, Float)) {
    return (source[1], source[0]);
}

val original = (3, 4.5);
val rotated = rotate(original); // (Float, Int)
~~~

生成的 MIL 保留元组签名和调用，可作为 `.mil` 入口再次编译。对象方法使用同样的私有槽协议，隐藏的 `this` 参数位于元组参数之前；虚方法和 `super.method(...)` 都会在调用返回后快照每个结果元素。包含 `String` 的元组仍等待相应布局完成；编译器不会将聚合压成单个 mlog 数值。

### 数组

数组是元素类型一致、定长的可索引序列。数组长度不写入类型，而由初始化字面量确定：

~~~mpl
val array: Int[] = [1, 2, 3, 4, 5];
var path: Float[] = [16.0, 32.0, 48.0];
val inferred = [1, 2, 3];       // 推导为 Int[]
val mixed = [1, 2.5];           // 推导为 Float[]
~~~

空数组没有元素可用于推导，必须有类型标注：

~~~mpl
val empty: Int[] = [];
~~~

`var` 数组可使用 `set` 修改已有元素，`val` 数组不允许修改：

~~~mpl
var queue: Int[] = [10, 20, 30];
queue.set(1, 25);
~~~

`set` 的下标可以是编译期已知且不越界的非负 `Int` 字面量，也可以是下述标准计数循环中被证明安全的下标。数组不能增删元素或整体重新赋值；声明初始化可以按值复制一个已知长度数组。

~~~mpl
for (var i: Int = 0; i < queue.size; i += 1) {
    queue.set(i, queue[i] + 1);
}
~~~

`Int[]`、`Float[]` 和 `Bool[]` 可作为顶层函数参数或返回值。长度不进入公开类型名，而是由编译器沿无环调用图从字面量、具名数组和返回路径传播：

~~~mpl
fun rotate(values: Int[]) {
    return [values[2], values[0], values[1]];
}

val source = [1, 2, 3];
val rotated = rotate(source); // Int[]，私有 ABI 形状为 3
~~~

数组参数与返回值按元素快照到独立 ABI 槽，因此 `consume(produce())` 中内层返回只执行一次，且写入外层参数前不会被覆盖。当前每个函数 ABI 专门化只接受一种长度；同一函数同时以不同长度调用会在编译期报错。

### List 与 Set

`List<T>` 是有序只读序列；`Set<T>` 是无序只读成员集合。两者使用工厂创建：

~~~mpl
val targets: List<Int> = List.of(4, 8, 15, 16);
val aliases = List.of("north", "east");

val allowed: Set<Int> = Set.of(1, 3, 5);
val priorities = Set.of(10, 20, 30);
~~~

有元素时，`T` 由元素推导；空集合需要目标类型：

~~~mpl
val noTargets: List<Int> = List.of();
val noIds: Set<Int> = Set.of();
~~~

当前 `Set` 只接受互不重复的静态字面量。这保证 Set 真的具有去重语义，而不是在没有动态 Memory runtime 时降级为数组。`List` 和 `Set` 都不可修改，也不能整体复制或重新赋值。

### MutableList

`MutableList<T>` 是具有**编译期固定容量、运行时可变长度**的有序序列。容量不属于公开类型身份，必须在初始化时确定：

~~~mpl
var values: MutableList<Int> = MutableList.withCapacity(8);
values.add(4);
values.add(8);
values.set(1, 9);
val current: Int = values.size;
val first: Int = values.get(0);
values.clear();
~~~

`MutableList.of(a, b, ...)` 创建容量等于初始元素数的列表；需要后续追加时使用显式类型和 `MutableList.withCapacity(n)`。当前 MutableList 元素限制为 `Int`、`Float`、`Bool`，因为这些元素可直接映射到 mlog/Memory 单元；字符串和嵌套聚合将在独立 Runtime 完成后加入。

`add(value)`、`clear()` 以及会改变长度的操作必须位于编译器可以线性证明的路径中，不能出现在 `if`、循环或函数调用内部；超过容量的追加是编译期错误。`set(index, value)` 与动态 `get(index)` 只能使用编译器证明在当前长度内的下标，推荐使用 `0 <= i < values.size` 的标准计数循环。列表的元素槽由物理 Memory 自动规划，MPL/MIL 不暴露 `read`、`write` 或长度槽名称。

## 通用访问与遍历

元组、数组、List、Set、MutableList 都支持常量下标读取和 `size`：

~~~mpl
val point: (Int, Int) = (12, 34);
val values: Int[] = [3, 6, 9];
val items = List.of(7, 8, 9);

val y: Int = point[1];
val first: Int = values.get(0);
val count: Int = items.size;
~~~

数组、List、Set、MutableList 还支持成员测试：

~~~mpl
if (values.contains(6)) {
    // ...
}
~~~

集合长度和下标均在编译期证明。动态下标当前仅用于元素为 `Int`、`Float` 或 `Bool` 的具名 Array/MutableList，且只接受 `for (var i = 0; i < container.size; i += 1)` 证明形式。List、Set、元组的运行时下标、取元素失败返回 `null`、切片和迭代器对象尚未启用；越界或无法证明的下标会报告 `MPL3601`，不会生成可能错误的 mlog。

所有同构元组、数组、List、Set、MutableList 可用于 `for`：

~~~mpl
var total: Int = 0;
for (var value : values) {
    if (value == 6) {
        continue;
    }
    total += value;
    if (total > 10) {
        break;
    }
}
~~~

异构元组没有统一元素类型，不能直接 `for`，但仍可按常量下标读取。`break` 和 `continue` 遵守普通循环语义，分别跳出整个遍历和进入下一个静态元素。

### 查询 Set 与通用集合接口

`Unit.getAll类型()` 与 `Building.getAll类型()` 的公开返回类型分别是 `Set<Unit<T>>` 和 `Set<Building<T>>`。它们不是额外的 MPL 类型名，也不要求用户知道链接、flag、重连或 profile lowering 的内部表示：

~~~mpl
val turrets: Set<Building<Duo>> = Building.getAllDuo();
val active: Set<Unit<Dagger>> = Unit.getAllDagger().where(_.alive);

val count: Int = turrets.size;
val first: Building<Duo>? = turrets.get(0);
for (var turret : turrets) {
    turret.enabled = false;
}
~~~

这与 Java 中以 `Map` 作为公开变量类型、由具体实现负责存储的关系相同：MPL 程序仅依赖 `Set<T>`，编译器可按来源选择静态元素槽、Unit 查询 Runtime 或具名建筑链接描述符。静态 `Set<T>`、Unit Set 和 Building Set 都支持读取 `size`、`get(index)` 与 `for`；返回值是否可空和访问的代价由来源决定。

`.where(...)` 是惰性游戏对象查询的筛选操作，`Unit` 额外支持稳定认领 `.take(n)`；它们不是静态 Set 的通用高阶函数。静态 Set 的 `contains(...)` 则由编译期已知元素展开。这样不会通过一个伪造的 `LinkedBuildingSet` 或 `UnitSet` 类型泄漏 Runtime 细节，同时也不会把弱一致扫描误承诺为静态集合快照。

## 当前限制与后续演进

- 容器元素不能是元组、数组、List、Set 或 MutableList；嵌套布局需要独立的 Memory runtime。
- 顶层函数与对象方法支持纯 `Int`/`Float`/`Bool` 元组及固定形状的 `Int[]`/`Float[]`/`Bool[]`（数组目前仅限顶层函数）参数和返回；List、Set、MutableList、String 元组仍需独立存储布局。
- `MutableList<T>` 已支持容量化 `add`、`set`、`get`、`removeAt`、`clear`、`size` 和遍历；可变 Set 与动态容器函数 ABI 仍待后续 Runtime。
- 字符串元素可声明和遍历；其按值复制使用有界动态字符串运行时，容量仍必须在编译期可证明。
- Unit/Building 查询是游戏对象的惰性 `Set<T>` 实现，不是静态元素快照；它们的筛选、弱一致性与重连规则见《单位遍历与私有运行时（讨论稿）》。

这组限制都是构建期失败，不提供运行时异常或隐式降级。构建报告应在后续版本记录每个静态聚合占用的私有变量槽和由此带来的指令数。
