# 单位与建筑遍历、私有运行时（讨论稿）

> 状态：单位遍历的表面语法已确认；单位扫描、flag 分配与嵌套循环的低层实现仍待原型验证。

## 表面语法

MPL 以 Unit 与 Building 命名空间的类型遍历方法提供对象遍历：

~~~mpl
for (var unit : Unit.getAllAlpha()) {
    unit.move(100, 80);
    unit.mine(100, 80);
}

for (var turret : Building.getAllDuo(_.enabled)) {
    turret.shoot(targetX, targetY, true);
}
~~~

Unit.getAllAlpha() 与 Building.getAllDuo() 是编译器根据目标 Mindustry 版本内容表生成的 API。Alpha 与 Duo 分别编码在方法名中；它们不是用户可变变量，也不是字符串。

getAll类型() 返回惰性的、不可变的可迭代查询对象，而不是真实数组：

~~~mpl
val damaged = Unit.getAllAlpha().where(unit => unit.health < 50);

for (var unit : damaged) {
    unit.move(100, 80);
}
~~~

第一版 `UnitSet<T>` / `LinkedBuildingSet<T>` 可保存为 `val` 并重复用于 for；它们不能存入对象字段、跨包导出或构造快照数组。每次进入 for 都创建新的私有迭代状态。`where(...)` 是惰性过滤，不预先扫描或分配单位列表。

类型遍历可接受内联过滤 lambda：

~~~mpl
Unit.getAllAlpha(unit => unit.health < 50)
Unit.getAllAlpha(_.health < 50)
~~~

_ 是唯一参数的简写。过滤 lambda 只用于遍历，并在当前候选对象上内联执行。

## 循环变量

unit 的静态类型为 `Unit<Alpha>`。它是借用对象：仅在本次循环体内有效，指向当前已被处理器绑定的单位。Building 遍历变量的类型为 `LinkedBuilding<Duo>`；它只可能来自 `.mplh` 声明的链接集合。

~~~mpl
for (var unit : Unit.getAllAlpha()) {
    unit.move(x, y);      // 合法：控制当前单位
    var health = unit.health; // 合法：读取当前单位快照
}

// unit 在此处不存在
~~~

借用对象不能赋给普通变量、作为返回值使用、存入数组，或传给可能在当前循环结束后保存它的 API。这样可避免把“当前绑定单位”误解为可长期保存的对象引用。

## flag 与私有管理 runtime

源语言不暴露 flag：不存在 `unit.flag` 属性，也不存在直接读写该值的 MPL/MIL API。

v146 源码复核后，flag 不能再被视为无副作用的私有 ID：写入它需要 `ucontrol flag`，会接管单位 LogicAI；其他处理器可覆盖该值，游戏 RTS AI 也会使用非零 flag。因此普通 `UnitSet` 遍历不以 flag 为基础。

未来若提供跨循环的“认领/管理”对象，应作为单独的 `UnitManager` runtime，而非 `UnitSet` 的隐式行为。它必须先冻结：

- owner token 的生成、处理器移动/复制后的语义；
- 多个处理器争夺同一单位时的合作约定；
- 原始 flag 的保存、恢复、死亡和重新生成单位的回收；
- RTS AI 与其他 mlog 脚本使用 flag 时的部署限制。

在这些规则冻结前，编译器不承诺 flag 管理的独占性或长期对象身份。

## 计划中的降级过程

~~~text
UnitSet 遍历入口
  → ubind Alpha 的下一候选单位
  → 空候选时跳转至循环出口
  → 对当前借用 Unit 执行过滤 lambda
  → 在宏中间语言中将 @counter 设为循环体入口

循环体结束或 continue
  → 在宏中间语言中将 @counter 设为单位遍历入口

break
  → 在宏中间语言中将 @counter 设为循环出口
~~~

循环体内的 Unit 方法直接作用于当前绑定单位，无需为每次调用按 ID 重新扫描。这是该语法优先于持久单位句柄的原因。v146 的 `ubind` 轮转顺序并非快照；单位生成、死亡、队伍变化或被其他处理器接管时，遍历只保证弱一致性。

## 待验证与待决议事项

1. 同类型 `ubind` 的终止算法：其游标在单个处理器内共享，首版应禁止同类型嵌套遍历；
2. 哨兵单位死亡、生成/销毁和缓存顺序变化时的弱一致遍历终止策略；
3. `ucontrol` / `uradar` / `ulocate` 会接管单位而非纯读取，控制 API 是否需要显式 `claim` / `release`；
4. 函数调用期间是否允许携带借用 Unit，或第一版只允许在循环体内直接使用；
5. `Building.getAll<T>()` 在 v146 普通处理器只能表示 `.mplh` 链接集合，不能表示地图全部同类建筑；
6. 后续是否提供 `UnitManager` / ManagedUnit 句柄；若提供，必须先解决 flag 的副作用与多处理器冲突。

在这些问题验证前，第一版实现可限制嵌套单位遍历与借用 Unit 的跨函数传递。
