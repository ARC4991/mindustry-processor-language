# 单位遍历与私有运行时（讨论稿）

> 状态：单位遍历的表面语法已确认；单位扫描、flag 分配与嵌套循环的低层实现仍待原型验证。

## 表面语法

MPL 以单位类型对象的 getAll() 方法提供单位遍历：

~~~mpl
for (var unit : Alpha.getAll()) {
    unit.move(100, 80);
    unit.mine(100, 80);
}
~~~

Alpha 是编译器内建单位类型对象，对应 Mindustry 的 @alpha。类型对象由目标 Mindustry 版本的内容表生成；它不是用户可变变量，也不是字符串。

getAll() 不返回真实数组，而是一个只供该 for 语句消费的惰性单位序列。因此第一版不允许：

~~~mpl
var units = Alpha.getAll(); // 错误：单位序列不能脱离 for 使用
~~~

## 循环变量

unit 的静态类型为 Unit。它是借用对象：仅在本次循环体内有效，指向当前已被处理器绑定的单位。

~~~mpl
for (var unit : Alpha.getAll()) {
    unit.move(x, y);      // 合法：控制当前单位
    var health = unit.health; // 合法：读取当前单位快照
}

// unit 在此处不存在
~~~

借用对象不能赋给普通变量、作为返回值使用、存入数组，或传给可能在当前循环结束后保存它的 API。这样可避免把“当前绑定单位”误解为可长期保存的对象引用。

## 私有 flag 约定

为了标识 MPL 已处理或已受管的单位，runtime 计划将游戏单位的 flag 作为私有 ID 使用。源语言不暴露 flag：不存在 unit.flag 属性，也不存在直接读写该值的 MPL API。

这不是对游戏层 flag 的物理隐藏。其他原始 mlog 处理器仍可能读取或改写它。因此应遵守以下约定：

- 被 MPL runtime 管理的单位，其 flag 由 MPL 独占；
- 不得在其他逻辑中为同一批单位实现另一个 flag 协议；
- runtime 使用保留数值区间，并允许在编译配置中指定基址；
- 用户源代码不能声明或引用编译器生成的 runtime 变量、flag 与内存槽位。

## 计划中的降级过程

~~~text
单位遍历入口
  → 绑定 Alpha 类型的下一候选单位
  → 读取并确认 runtime 私有 ID
  → 没有候选单位时跳转至循环出口
  → 将 @counter 设为循环体入口

循环体结束或 continue
  → 将 @counter 设为单位遍历入口

break
  → 将 @counter 设为循环出口
~~~

循环体内的 Unit 方法直接作用于当前绑定单位，无需为每次调用按 ID 重新扫描。这是该语法优先于持久单位句柄的原因。

## 待验证与待决议事项

1. 不同 Mindustry 版本中，ubind 轮换同类型单位的顺序、终止检测与空结果行为；
2. 在单位死亡、生成或被其他处理器抢占期间，单次遍历的稳定性；
3. 嵌套单位遍历时，内层遍历结束后如何以私有 ID 恢复外层绑定；
4. 函数调用期间是否允许携带借用 Unit，或第一版只允许在循环体内直接使用；
5. 后续是否提供可跨循环保存的 ManagedUnit 句柄；若提供，它将使用较慢的“按私有 ID 重新定位”路径。

在这些问题验证前，第一版实现可限制嵌套单位遍历与借用 Unit 的跨函数传递。
