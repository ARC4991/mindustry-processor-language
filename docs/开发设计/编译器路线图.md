# 编译器路线图

> 状态：规划稿。实现语言确定为 Java（JDK 17）；解析器倾向使用 ANTLR 4。

## 目标流水线

~~~text
.mpl / .mil 源文件
  → 词法 / 语法分析
  → AST
  → 名称解析与作用域分析
  → 类型检查、常量求值与控制流检查
  → 宏中间语言（MIL，暂定名称）
  → 全项目优化、资源布局与分片计划
  → 宏展开、标签与地址解析
  → 每处理器 mlog 代码生成与校验
  → 单份 .mlog 或多处理器部署包输出
~~~

目标 profile 在语义分析后、代码生成前参与：它提供内容类型、硬件容量、指令能力与特权限制，并为同一个高层 IR 选择基线或版本专用 lowering。首批 profile 为 v146 与 v159.7；每个构建只选择其中一个。

每一阶段都应保存来源位置，并将诊断以“文件、行、列、错误码、说明”的形式交给调用方。前端即使发现多个错误，也应尽量继续恢复并一次报告，避免用户反复编译。

## 分阶段交付

1. **profile 基础设施**：为 v146、v159.7 提取并审查指令/内容/硬件描述，建立差异报告和 profile 选择诊断。
2. **前端最小闭环**：实现字面量、变量、赋值、算术表达式和诊断；输出 AST 供测试。
3. **控制流**：实现 if、循环、break、continue，输出基础 jump 结构；以对 @counter 的写入实现间接跳转。
4. **函数与宏中间语言**：以 @counter 实现 return 的间接跳转；确定嵌套调用的返回地址保存策略，实现可独立编写的宏中间语言及其基础游戏宏。
5. **对象遍历运行时**：实现 Unit.getAll类型() 与 Building.getAll类型() 的弱一致 lowering，以及私有的 `ubind`、UnitRef 哨兵、flag 标签、重绑与控制冲突诊断；用户侧只保留 Unit 查询、筛选和直接对象操作。
6. **字符串运行时**：实现全局字符输出表、字符串序列及 print 输出分发；在 v159.7 选择 printchar/format 等等价优化。
7. **硬件与内存**：项目/包 `.mplh`、profile 屏幕规格、同规格组合屏、包尺寸约束、部署清单和动态 Array 物理内存自动布局已实现；后续完善对象池与跨 shard 全局预算，不向 MPL/MIL 源码暴露内存读写。
8. **模块与对象**：项目内及锁定 `workspace:` 包的 import/export、MPL/MIL 混合模块图、循环诊断、私有符号隔离、target/profile 校验和硬件依赖注入已实现；后续实现 registry、访问控制与无继承 class/new。
9. **数据结构**：在内存模型明确后实现数组、元组与解构。
10. **优化与工具链**：已实现 HIR 纯常量折叠、常量分支/`while(false)` 裁剪、基本不可达语句删除，并在 `report.json` 记录统计；后续实现活跃区间槽位复用、源映射（若可行）与 profile 专用 lowering 报告。
11. **多处理器部署**：解析 `.mplh` 处理器拓扑，产出部署清单与每片独立 mlog；实现共享 Memory 的单写者/SPSC 邮箱、每片限制校验和硬件检查。只分离已证明独立的 runtime/任务，不能硬切顺序控制流。

## 目录约定

- src/main/java：编译器实现。
- src/main/antlr：ANTLR 词法与语法定义。
- src/main/resources：内建符号表等运行时资源。
- src/test：单元测试、端到端编译用例与期望 mlog 输出。
- docs/语法设计：面向语言使用者的规范与讨论记录。
- docs/开发设计：编译器架构、约定和路线图。
- docs/示例：可阅读的 MPL/MIL 示例；只有已实现的特性才可标为“可运行”。

## 首批验收条件

- 给定一个 .mpl 文件，能报告稳定且带位置的词法/语法错误。
- 相同输入生成确定性的 mlog 文本。
- 每项已实现语法都有成功与失败测试；端到端测试直接比较 mlog 输出。
- 文档中的“已确认”语法与 ANTLR 文法一致。
