# 编译器路线图

> 状态：规划稿。实现语言确定为 Java（JDK 17）；解析器倾向使用 ANTLR 4。

## 目标流水线

~~~text
.mpl 源文件
  → 词法 / 语法分析
  → AST
  → 名称解析与作用域分析
  → 类型检查、常量求值与控制流检查
  → 宏中间语言（MIL，暂定名称）
  → 宏展开、标签与地址解析
  → mlog 代码生成与优化
  → .mlog 输出
~~~

每一阶段都应保存来源位置，并将诊断以“文件、行、列、错误码、说明”的形式交给调用方。前端即使发现多个错误，也应尽量继续恢复并一次报告，避免用户反复编译。

## 分阶段交付

1. **前端最小闭环**：实现字面量、变量、赋值、算术表达式和诊断；输出 AST 供测试。
2. **控制流**：实现 if、循环、break、continue，输出基础 jump 结构；以对 @counter 的写入实现间接跳转。
3. **函数与宏中间语言**：以 @counter 实现 return 的间接跳转；确定嵌套调用的返回地址保存策略，实现可独立编写的宏中间语言及其基础游戏宏。
4. **对象遍历运行时**：实现 Unit.getAll类型() 与 Building.getAll类型()，验证单位轮换、私有 flag、建筑链接与循环终止策略。
5. **字符串运行时**：实现全局字符输出表、字符串序列及 print 输出分发；确定拼接序列的内存策略。
6. **硬件与内存**：解析硬件声明文件，实现组合屏幕、物理内存的编译期检查与虚拟内存分配。
7. **模块与对象**：实现包解析、import/export、访问控制、硬件依赖注入与无继承 class/new。
8. **数据结构**：在内存模型明确后实现数组、元组与解构。
9. **优化与工具链**：常量折叠、死代码消除、源映射（若可行）和命令行接口。

## 目录约定

- src/main/java：编译器实现。
- src/main/antlr：ANTLR 词法与语法定义。
- src/main/resources：内建符号表等运行时资源。
- src/test：单元测试、端到端编译用例与期望 mlog 输出。
- docs/语法设计：面向语言使用者的规范与讨论记录。
- docs/开发设计：编译器架构、约定和路线图。
- docs/示例：可阅读的 MPL 示例；只有已实现的特性才可标为“可运行”。

## 首批验收条件

- 给定一个 .mpl 文件，能报告稳定且带位置的词法/语法错误。
- 相同输入生成确定性的 mlog 文本。
- 每项已实现语法都有成功与失败测试；端到端测试直接比较 mlog 输出。
- 文档中的“已确认”语法与 ANTLR 文法一致。
