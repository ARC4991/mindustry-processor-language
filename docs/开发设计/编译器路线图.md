# 编译器路线图

> 状态：规划稿。实现语言确定为 Java（JDK 17）；解析器倾向使用 ANTLR 4。

## 目标流水线

~~~text
.mpl / .mil 源文件
  → 词法 / 语法分析
  → AST
  → 名称解析与作用域分析
  → 类型检查、常量求值与控制流检查
  → 宏中间语言（MIL，暂定名称）
  → 全项目优化、资源布局与分片计划
  → 宏展开、标签与地址解析
  → 每处理器 mlog 代码生成与校验
  → 单份 .mlog 或多处理器部署包输出
~~~

目标 profile 在语义分析后、代码生成前参与：它提供内容类型、硬件容量、指令能力与特权限制，并为同一个高层 IR 选择基线或版本专用 lowering。首批 profile 为 v146 与 v159.7；每个构建只选择其中一个。

每一阶段都应保存来源位置，并将诊断以“文件、行、列、错误码、说明”的形式交给调用方。前端即使发现多个错误，也应尽量继续恢复并一次报告，避免用户反复编译。

## 分阶段交付

1. **profile 基础设施**：为 v146、v159.7 提取并审查指令/内容/硬件描述，建立差异报告和 profile 选择诊断。
2. **前端最小闭环**：实现字面量、变量、赋值、算术表达式和诊断；输出 AST 供测试。
3. **控制流**：实现 if、循环、break、continue，输出基础 jump 结构；以对 @counter 的写入实现间接跳转。
4. **函数与宏中间语言**：以 @counter 实现 return 的间接跳转；确定嵌套调用的返回地址保存策略，实现可独立编写的宏中间语言及其基础游戏宏。
5. **对象遍历运行时**：实现 Unit.getAll类型() 与 Building.getAll类型() 的弱一致 lowering，以及私有的 `ubind`、UnitRef 哨兵、flag 标签、重绑与控制冲突诊断；用户侧只保留 Unit 查询、筛选和直接对象操作。
6. **字符串运行时**：全局 UTF-16 输出表、物理序列、描述符表、动态拼接、长度/相等、函数值复制、print 输出分发和跨函数容量传播已实现；v159.7 已用 `printchar` 直接输出动态代码单元并记录 profile 优化差值，后续实现受限 `format` 与活跃区间复用。
7. **硬件与内存**：项目/包 `.mplh`、profile 屏幕规格、同规格组合屏、包尺寸约束、部署清单、动态 Array 与唯一所有权对象池的物理内存自动布局已实现；后续完善跨 shard 全局预算，不向 MPL/MIL 源码暴露内存读写。
8. **模块与对象**：项目内及锁定 `workspace:` 包的 import/export、MPL/MIL 混合模块图、循环诊断、私有符号隔离、target/profile 校验、硬件依赖注入、public/private、单继承 class、`super`、签名重载、虚方法派发、顶层静态 new、非逃逸局部分配点复用和工厂所有权转移已实现；后续实现 registry、共享引用、跨分配点活跃区间复用、interface 与显式资源协议。
9. **数据结构**：在内存模型明确后实现数组、元组与解构。
10. **优化与工具链**：已实现 HIR 纯常量折叠、常量分支/`while(false)` 裁剪、基本不可达语句删除，以及统一 mlog 度量和 profile 专用 lowering 差值报告；后续实现活跃区间槽位复用、源映射（若可行）与更多 target lowering。
11. **多处理器部署**：`ShardPlan` / `RuntimeTopologyPlan`、最终代码每片限制校验、多处理器紧密蓝图、每片独立 MIL/mlog、共享 Runtime Memory 自动连接、连接半径校验、双阶段启动握手、固定宽度单写者/SPSC 邮箱、带独立心跳和确认 shutdown 的 Worker 调度，以及纯数值 helper 的效果分析、调用图分量同片、真实 target 函数成本与确定性多 Worker 均衡已实现；后续实现通用所有权转移、硬件检查、异步成本模型和用户并发。不能硬切顺序控制流。

## 目录约定

- src/main/java：编译器实现。
- src/main/antlr：ANTLR 词法与语法定义。
- src/main/resources：内建符号表等运行时资源。
- src/test：单元测试、端到端编译用例与期望 mlog 输出。
- docs/语法设计：面向语言使用者的规范与讨论记录。
- docs/开发设计：编译器架构、约定和路线图。
- docs/示例：可阅读的 MPL/MIL 示例；只有已实现的特性才可标为“可运行”。

## 首批验收条件

- 给定一个 .mpl 文件，能报告稳定且带位置的词法/语法错误。
- 相同输入生成确定性的 mlog 文本。
- 每项已实现语法都有成功与失败测试；端到端测试直接比较 mlog 输出。
- 文档中的“已确认”语法与 ANTLR 文法一致。
