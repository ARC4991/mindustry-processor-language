# V159.7 目标配置（讨论稿）

> 状态：MPL 支持的最新目标配置。本文以用户提供的 `Mindustry-159.7.zip` 中源码为依据；它与 v146 共存，不替换 v146 的代码生成规则。

## 范围

目标选择精确到游戏版本：

```json
{
  "target": {
    "mindustry": "v159.7"
  }
}
```

每次构建只选择一个 target profile：单处理器项目产出一份 mlog，多处理器项目产出同一 target 的部署包和多份 mlog。相同 MPL/MIL 项目可分别构建 v146 与 v159.7 产物；不能把含 v159.7 专属指令的产物部署到 v146。

## 与 v146 共同的硬件限制

源码中以下值未变，两个 profile 可共享同一基础硬件描述：

| 项目 | 值 |
| --- | --- |
| Micro / Logic / Hyper Processor IPT | 2 / 8 / 25 |
| Memory Cell / Memory Bank | 64 / 512 槽 |
| 单处理器 graphics buffer | 256 命令 |
| Display flush 限制 | 现有命令加本次命令严格小于 1024 |
| print 可见文本上限 | 400 字符 |

依据：`core/src/mindustry/content/Blocks.java` 与 `core/src/mindustry/logic/LExecutor.java`。

## 已确认的 Logic 增量

| v159.7 指令能力 | 对 MPL 的处理策略 |
| --- | --- |
| `select`：按条件在两个值中选择 | 仅在两个分支已经是无副作用的已求值值时优化 MPL 条件表达式；v146 保留跳转式 lowering |
| `printchar` | 可优化单个动态 UTF-16 代码单元输出；不改变 v146 字符串表的公开表示 |
| `format` | 可优化受限的 `{0}`…`{9}` 占位符替换；不改变 MPL `String` 的公开拼接语义 |
| `unpackcolor` | 可优化 Color 分量拆解；是否公开为 Color API 待定 |
| `draw print` | 可作为 v159.7 专属 Display 文本能力；v146 没有等价的普通处理器实现，不能伪装成跨版本 API |
| 链接 LogicBuild 的变量读写 | 可在严格效果、所有权和部署条件下优化少量内部邮箱访问；跨版本 ABI 仍使用共享物理 Memory，不能公开为共享变量 |
| Query、天气、子弹生成、音频/音乐、标记、客户端数据等 | 先列入 profile 能力表；多数需特权/世界处理器，第一版标准处理器 API 不公开 |

v159.7 同时改进了 `print`：追加字符串时按剩余容量截断，因此 400 字符上限更稳定；但 MPL 仍应把 400 作为跨 profile 的可见输出上限。

`select` 的两个候选值在执行 `select` 前都已是 mlog 变量；它不保留 MPL 条件表达式“只求值一个分支”的副作用语义。因此只要任一分支包含函数调用、I/O、宏或可能暂停的 runtime，优化器就必须回退为 v146 的跳转 lowering。

`printchar` 对数值执行 `floor` 后转为 Java `char`，故只可用于已证明在 `0..65535` 的一个 UTF-16 代码单元。`format` 每次只替换文本缓冲中编号最小的一个 `{n}` 占位符，且仍受 400 上限。`draw print` 会消费当前 text buffer，并按 glyph 展开为多个图形命令；它受 256 图形缓冲上限，不能作为普通 `Message.print` 的透明替代。

v159.7 的 LogicBuild 实现了可读写接口：已链接的另一个处理器可按变量名访问其变量。这不是 v146 的能力，变量也会随对方代码重载改变，并且没有原子读改写保证。因此 MPL 不把它定义为源语言的跨处理器内存；共享 Memory + 单写者邮箱仍是所有 profile 的通信 ABI。profile 只能在保持同一消息顺序、所有权和部署检查的前提下，将少量内部访问优化为该能力。

## 特权能力边界

v159.7 的 `QueryI`、部分规则修改、天气、子弹、音频、标记和客户端数据等能力可能只在 world/privileged processor 生效。profile 必须为每项指令标记至少以下字段：

- `standard`：普通处理器可用；
- `worldOnly`：仅世界/特权处理器可用；
- `clientOnly` 或 `headlessNoop`：服务器或无界面环境中不可观察；
- `since`：首次支持该能力的 Mindustry 版本。

普通 `.mplh` 的 `Processor` 硬件声明必须声明处理器类别。若包请求 `worldOnly` 能力而宿主只有普通处理器，链接直接失败。

此外，v159.7 的 `UnitBindI` 会在普通处理器且地图规则 `logicUnitControl` 被关闭时直接不执行。因此 `Unit.getAll类型()` 与 Unit 控制不能只声明“目标版本支持”，还必须在项目/包的部署需求中声明 `logicUnitControl: true`。编译器负责检查 profile 和生成部署检查项；地图规则本身不是纯编译期事实，部署检查失败时不得假装 Unit API 会正常工作。

## 源码依据

- `core/src/mindustry/logic/LExecutor.java`：`SelectI`、`PrintCharI`、`FormatI`、`UnpackColorI`、`QueryI`、`SpawnBulletI`、天气/音频/标记相关实现；
- `core/src/mindustry/logic/LStatements.java`：对应 mlog 语句和参数形式；
- `core/src/mindustry/content/Blocks.java`：处理器、内存与 world block 配置。
