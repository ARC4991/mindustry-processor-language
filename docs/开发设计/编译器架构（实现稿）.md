# 编译器架构（实现稿）

> 状态：v146 基线的实现架构。本文固定编译器各层的职责、数据流和第一版函数 ABI；尚未冻结的语言功能会明确标为后续阶段，而不会渗入首个闭环。

## 目标

编译器以 Java 17 实现。每次构建读取一个项目、一个精确 target profile 和一个入口文件，产出确定性的单份 mlog 或多处理器部署包、诊断列表与资源使用报告。多处理器部署包可额外包含只含处理器和 Memory 的运行时蓝图；Display、Message 等地图业务硬件始终作为蓝图外的部署契约。未声明处理器拓扑的项目始终产出单份 mlog。

```text
项目文件 / 包文件 / .mplh
        ↓
词法与语法 → AST → 名称与类型语义 → HIR
        ↓                         ↘ 资源/硬件需求
v146 profile 校验 → 全项目优化 → ShardPlan
                                       ↓
              每 shard：高级糖降级 → 源级 MIL → 宏展开与目标 lowering → mlog
                                                                      ↓
                                                             目标限制校验 → 部署清单 / 构建报告
```

MPL 与 MIL 共用项目、符号、类型、profile 和诊断框架；差异只在前端与降级起点。MPL 不允许 `@`，MIL 可以使用 profile 提供的基础宏。MIL 保留变量、表达式、函数和结构化控制流等基础语法；每 shard 的高级糖降级只把 Unit/Building、字符串 runtime 等需要游戏专用实现的节点替换为宏，不把普通语句逐条包装为 mlog 指令。

## Java 包与职责

| 包 | 职责 | 不负责 |
| --- | --- | --- |
| `com.arc.mpl.cli` | 命令行参数、退出码、文本/JSON 诊断输出 | 语言语义 |
| `project` | `mpl.json`、依赖图、入口、`.mplh` 和包目标兼容性 | mlog 生成 |
| `profile` | v146/v159.7 内容、硬件、指令、权限、限制与 lowering 能力 | 解析用户源码 |
| `syntax` | ANTLR 词法/语法、错误恢复、AST 构建 | 类型推导 |
| `ast` | 无副作用的 MPL/MIL 语法树与来源位置 | 目标版本判断 |
| `semantic` | 作用域、符号、类型、可空检查、控制流与资源需求收集 | 指令排布 |
| `hir` | 与 target 无关的高层 IR | 标签和 mlog 字符串 |
| `plan` | shard、硬件所有权、通信 ABI 与物理/虚拟布局 | MPL 表面语法或游戏布线 |
| `lower` | HIR → 源级 MIL、高级糖降级、函数 ABI/runtime 抽象与 profile 专用优化选择 | 文本序列化或原始 mlog 拼接 |
| `mil` | MIL 基础语法节点、profile 宏签名、宏卫生与宏展开 | MPL 表面语法或原始 mlog 文本 |
| `codegen` | 展开后目标程序的标签/地址解析、mlog 文本、源映射与最终指令/标签/token 限制校验 | 语言诊断策略 |
| `diagnostic` | 诊断模型、错误码、来源范围与恢复策略 | `System.err` 直接打印 |

所有阶段返回不可变结果对象。发现错误时保留尽可能多的占位节点继续分析，一次构建报告多个错误；只有存在 error 级诊断时才不写最终 mlog。

### 诊断与本地化

每个诊断都有稳定错误码；可本地化文本另外使用稳定的 `messageKey` 与参数，不能把翻译后的文字当作程序接口。首个 catalogue 为 `zh-CN`，也是默认语言；CLI 可显式传入 `--lang=zh-CN`。未来增加语言时，只新增 `DiagnosticLanguage` 项和对应资源目录，既不改变错误码，也不改变编译阶段。

编译器/项目读取诊断和 CLI 的成功、用法、写入信息已经走 catalogue；尚未迁移的语法与语义诊断暂时保留其中文源文本作为安全回退。即使某个未来语言缺少 key，也必须显示默认中文而不是丢失错误码或以异常中断构建。

## 中间表示

### AST

AST 保留用户拼写与精确的 `SourceSpan`，用于诊断和格式化。它不包含推导后的类型、链接编号或已选择的目标指令。MPL AST 不会出现 `@`；MIL AST 可以保留用户写下的 profile 宏名，但尚未把它解析为任何 mlog 指令。

### HIR

HIR 表达已验证的 MPL/MIL 语义，例如 `HirIf`、`HirLoop`、`HirCall`、`HirPrint`、`HirUnitIteration` 与通过 profile 校验的 MIL 宏调用。每个值有明确类型，每个硬件引用都已关联 `.mplh` 或包注入声明。

HIR 不包含 mlog 标签、变量名、内存槽位或 profile 专属指令。这样同一 HIR 可分别给 v146 与 v159.7 选择不同 lowering。

### MIL

MIL 是**源级**中间表示，不是结构化控制流已经展开后的低层指令表示。它保留 `val`/`var`、表达式、普通调用、函数及 `if`/`while`/`for` 等结构化节点，并额外允许 profile 已声明的 `@` 基础宏。

`lower` 只在高层糖需要专用游戏实现时引入这些宏：例如 UnitSet 的私有认领和遍历、对象化 Unit/Building 操作、字符串表和输出运行时。普通加法、赋值、条件和循环仍保持 MIL 的正常节点，不能被表示成逐条对应 `set`、`op`、`jump` 的宏包装。MIL 也不把用户可见标签、目标临时变量或原始 `@counter` 跳转作为表面语法。

宏展开产生内部的目标程序表示；该表示才拥有卫生化临时变量、标签、跳转目标、函数 ABI 片段及 profile 选定的目标操作。宏展开、标签地址解析和来源回链必须是确定性的，使每个目标层错误都能从“mlog 指令 → 宏展开 → MIL 节点 → HIR/AST”定位回用户源文件。地址解析完成后，`MlogOutputValidator` 按 profile 拒绝超出 1000 指令、500 标签或单条 16 token 的产物；多处理器时必须对**每一个**输出 shard 单独校验，不能把游戏解析器的截断当成成功构建。

当前 target 发射器通过结构化 `MlogProgramBuilder` 表示 `set`、`op`、`jump`、`ubind`、`sensor`、`ucontrol`、输出与 `stop` 等最终目标指令；`MlogCodeGenerator` 在宏展开和 target lowering 之后只选择目标操作和操作数，不再自行散落拼接 mlog 文本。新指令要先进入这个受限接口，再由 profile/validator 补齐签名与权限校验。

### 构建模式与产物

一次成功的 `mpl build` 总会生成同名的两个文件：可粘贴到游戏的 `.mlog`，以及用于检查高级糖降级的 `.mil`。生成 `.mil` 保留基础 MPL 结构，只显式展示 profile 的**公开**宏与游戏层 alias；flag、owner token、UnitRef、内部标签、临时变量和内存槽位只存在于宏展开后的内部 IR。它不是已完成的 mlog lowering，也不应成为逐条 mlog 指令的包装格式。重新构建会覆盖该生成文件；设计上用户手写 MIL 应放在 `src/`，但当前实现尚未提供独立 MIL 的 ANTLR 解析、宏展开和 source map，故尚不能把手写 `.mil` 当成可构建输入。

默认 Release 模式把**最终 target lowering 引入的**跳转标签压缩为 `_0`、`_1`……，以减少 1000 条 mlog 指令预算内反复出现的字符；`mpl build --debug ...` 则保留 `mpl_while_start_0` 这类完整 lowering 名称。由于 `.mil` 仍是结构化形式，它通常不含这些生成标签。两种模式的 HIR、MIL 宏选择、指令数量和可观察游戏行为相同，只改变 `.mlog`（以及已展开 target 调试输出）中的标签拼写，便于在部署与调试间选择。

### ShardPlan

优化后的 HIR 先形成 `ShardPlan`，再进行每片 lowering。单处理器项目也有一个只含 `Main` 的计划，以避免未来把多处理器支持旁路接入代码生成。计划包含处理器类型、每片虚拟槽预算、共享物理段、单写者地址所有权、SPSC 通信边、硬件/I/O 所有者、私有 Unit runtime 所有者和每片的预估成本。

分片器不得按源代码行或地址硬切。它只移动效果分析证明独立的编译器 runtime 或未来显式任务；顶层顺序控制流、同步函数 ABI、硬件 I/O 和默认 Unit runtime 保留在 `Main`。若不可分割区域超过 1000 条，优化后仍须报错，不能用跨处理器通信静默改变程序顺序。

## v146 profile 与硬件流程

v146 是首个实现 profile。profile 采用《[Profile 与构建产物 Schema（讨论稿）](数据格式/Profile与构建产物Schema（讨论稿）.md)》的 JSON 数据格式，提供机器可读的：

- Micro/Logic/Hyper Processor 的 IPT、链接范围和权限类别；
- Memory Cell/Bank 的物理容量；
- Display/Message/Switch 等硬件类型和限制；
- 内容类型、`LAccess` 属性、Unit 控制动作和 mlog 指令签名；
- 指令可用性、worldOnly/clientOnly 限制与地图规则前提。

`.mplh` 先由 `project` 单独解析，只产生硬件、处理器拓扑与资源预算声明。随后语义阶段将包的硬件需求合并到项目需求；profile 负责验证真实 link 类型、组合屏幕尺寸、每个处理器能力、链接范围/权限和物理/虚拟预算。

业务 MPL/MIL 永远拿不到可下标读写的 Memory 对象。内存布局器接收 HIR 的对象、字符串、函数 ABI 和 runtime 需求，输出物理/虚拟预算明细及内部槽位映射。多处理器时虚拟槽按 shard 独立分配；共享物理段只暴露给自动生成的版本化邮箱和单写者区间，不能退化为各 shard 任意读写的全局变量表。

## 第一版函数 ABI

为让 v146 首个闭环可实现，第一版采用静态、不可重入调用约定：

1. 函数参数、局部变量、返回值和返回地址都分配为该函数专属的内部槽位；
2. 调用点把实参写入被调函数参数槽位，以 `op add return @counter 1` 保存下一条跳转指令之后的地址，再跳转到函数入口；
3. `return value` 写入返回值槽位，将 `@counter` 设为保存的返回地址；
4. 调用图不得有环，因此禁止直接/间接递归；同一函数在其尚未返回时不能再次进入；
5. 函数不允许捕获或保存借用 `Unit`；第一版函数体禁止开启任何 UnitSet 遍历；
6. 函数只能直接访问声明在它之前的顶层变量；语义分析沿无环调用图传递这些依赖，并验证每个顶层调用点已经完成全部依赖的初始化。

这种 ABI 支持 `A → B → C` 的嵌套普通调用，因为每个函数各自拥有一套槽位；它不支持 `A → B → A`。递归、闭包、异步和可重入函数进入后续 ABI 版本，届时须先定义静态最大栈深与内存预算。

## 顶层与跨 tick

编译器按 `main.mpl` 顶层语句的源顺序生成指令，不添加隐式主循环，并在末尾追加 v146 的 `stop`。`stop` 使 `@counter` 停在自身，因此默认程序只执行一次；需要持续逻辑时，用户必须显式编写 `while`。这避免把游戏处理器“越过末尾会重新取第 0 条”的目标行为误表现为 MPL 的主循环。

顶层初始化是普通赋值指令。若程序进入显式无限循环，循环前的初始化自然只会运行一次；若循环退出，末尾 `stop` 会停止处理器。第一版不引入 `state` 关键字；对象持久化、跨 tick 生命周期和显式 `new/delete` 在自动内存布局完成后再冻结。

## v146 最小闭环

首个可运行版本只实现以下功能：

1. `.mpl`、`.mil`、`mpl.json` 和项目 `.mplh` 的加载与位置诊断；
2. `Int`、`Float`、`Bool`、字面量、局部/顶层变量、赋值和基础算术；
3. `if`、`while`、`do-while`、计数式 `for`、`break`、`continue`（已实现）；
4. 非递归 `fun`、参数、返回值和上述静态 ABI（已实现）；
5. `Message.print(...)` 的数值与字符串字面量输出，以及硬件 link/类型校验；
6. HIR → v146 MIL → mlog 的确定性代码生成。

类、数组、`new`、包链接、String 动态拼接、组合 Display、Unit/Building 遍历、分片部署和 v159.7 专用优化不阻塞此闭环，但必须在各自阶段接入同一 HIR/profile/ShardPlan 架构，不能绕开它。

## 测试策略

| 层级 | 验证内容 |
| --- | --- |
| parser | AST 结构、错误恢复、行列位置 |
| semantic | 作用域、严格类型、不可变值、循环控制、递归拒绝、传递全局依赖与初始化顺序 |
| profile | v146 硬件容量、指令权限、目标不匹配与地图规则前提 |
| lowering | 同一 HIR 的预期源级 MIL、高级糖到 profile 宏的降级、函数 ABI 需求 |
| 宏展开 | 宏卫生、调用点来源链、内部标签/临时变量与资源成本 |
| codegen | golden mlog 文本、最终标签地址、变量命名确定性，以及指令/标签/token 上限拒绝 |
| shard plan | 单/多 shard 选择、所有权冲突拒绝、共享 Memory 布局与每片预算 |
| 多处理器端到端 | 多份 mlog、部署清单、邮箱 ABI 与每片独立限制校验 |
| end-to-end | `examples/` 项目、成功构建与预期失败用例 |

每个 v159.7 专用优化都必须复用相同 HIR 测试，并与 v146 baseline 的可观察行为对照。
