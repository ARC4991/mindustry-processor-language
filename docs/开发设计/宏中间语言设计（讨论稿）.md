# 宏中间语言设计（讨论稿）

> 状态：分层职责与 `.mil` 扩展名已确认；正式名称、宏定义语法与完整基础宏表待确认。本文暂以 MIL（Macro Intermediate Language）称呼该语言。

## 定位

MIL 同时承担两个角色：

1. MPL 的编译产物：承接单位 runtime、字符串表和其他高级概念的降级结果；
2. 性能敏感用户可直接编写的专家语言：可绕过 MPL runtime，但仍保留结构化控制流。

MPL 不出现 @。@ 只属于 MIL，用于调用映射到游戏基础能力的宏。

## 两阶段编译

~~~text
MPL
  → 语义分析与高级概念降级
  → MIL（结构化控制流 + 基础游戏宏）
  → 宏展开、标签与地址解析
  → 原始 mlog 指令
~~~

用户直接编写 MIL 时，从第二行开始进入流程。`mpl build` 现阶段会在 mlog 输出文件同目录自动写出同名 `.mil`：例如指定 `output.mlog` 时同时得到 `output.mil`。MIL 用于检查 lowering 与 runtime 展开；游戏中只粘贴 `.mlog`。编译器后续仍需补齐用户 `.mil` 的独立 ANTLR 入口、宏展开错误来源映射与 source map。

项目与包的 `src` 目录均可混合放置 `.mpl` 与 `.mil` 文件；它们进入同一个链接单元并共享类型、导出符号与全局资源预算。包也可用 `.mil` 实现其公开 API。每个项目/包仍各自拥有 `.mplh`：该文件只声明硬件和资源需求，不包含 MPL 或 MIL 业务代码。

## 共同的结构化核心

MPL 与 MIL 都支持变量、函数、if、while、for、break、continue 和 return。控制流不是用户手写地址，而由 MIL 编译器生成跳转；其实现可通过对 @counter 的写入完成间接跳转。

~~~text
while (running) {
    @unit.bind(@alpha);
    @unit.move(targetX, targetY);
}
~~~

上例是 MIL 示意：while 是结构化语言特性，@unit.bind 与 @unit.move 是基础游戏宏。具体宏名称和参数形式尚未冻结。

## 分层边界

| 能力 | MPL | MIL |
| --- | --- | --- |
| @ 宏 | 不允许 | 允许 |
| Unit.getAll类型() 与私有单位 runtime | 自动降级 | 用户自行选择是否实现 |
| String 与字符串表 | 自动降级 | 用户直接使用输出与跳转相关宏；字符串布局由链接器管理 |
| 结构化控制流与函数 | 支持 | 支持 |
| 游戏基础指令 | 高级 API 间接访问 | 通过 @ 宏直接访问 |

MIL 宏展开必须生成不会与用户变量冲突的内部标签、临时变量与内存槽位，并在诊断中保留宏调用位置。

物理/虚拟内存不向 MIL 暴露：用户不能声明 Memory、传递内存给包，或直接读写槽位。宏展开所需的临时变量和内部槽位由编译器从 `.mplh` 已声明的预算中自动分配；不足时是构建期错误。

## 当前生成产物格式

当前实现将已经完成 HIR lowering 的指令序列序列化为 `@logic.*` 宏。这样 `.mil` 不直接出现裸 `set`、`op`、`jump`、`ubind` 等游戏指令；每个目标操作都通过 profile 提供的宏边界表达。v146 已生成以下内部宏：

| MIL 宏 | target 展开 |
| --- | --- |
| `@logic.label(name)` | 跳转标签 |
| `@logic.set(target, value)` | `set` |
| `@logic.op(kind, result, left, right)` | `op` |
| `@logic.jump(target, condition, left, right)` | `jump` |
| `@logic.print(value)` / `@logic.printFlush(link)` | `print` / `printflush` |
| `@logic.unitBind(target)` / `@logic.sensor(...)` | `ubind` / `sensor` |
| `@logic.unitControl(command, ...)` | `ucontrol` |
| `@logic.stop()` | `stop` |

例如：

~~~mil
@logic.op(add, __mpl_tmp0, 1, 2);
@logic.set(mpl_total, __mpl_tmp0);
@logic.stop();
~~~

这里的 `@logic.*` 是 **compiler-generated macro namespace**，不是 MPL API，也不是让用户绕过权限、内存预算或 `flag` 保留规则的入口。生成的 `.mil` 带有“请勿直接编辑”注释；重新执行构建会覆盖它。待 MIL 前端完成后，手写 `.mil` 只可调用经过 profile 白名单验证的公开基础宏，仍不能直接使用保留操作。

正常构建的 `@logic.label(_0)` 使用最短的递增标签名，以减少 mlog 中反复出现的 token；`mpl build --debug ...` 则将同一位置显示为包含 lowering 角色的可读名称。两种模式的控制流、宏调用与可观察行为完全相同，`.mil` 和 `.mlog` 总是使用同一种标签风格。

## 独立语法与宏卫生（建议冻结）

MIL 不是“允许任意粘贴 mlog 的文本格式”。它拥有独立的 ANTLR 入口，但复用 MPL 的结构化块、变量、函数、类型、`if`/`while`/`for`/`break`/`continue`/`return` 语法；差异仅在于 MIL 允许 profile 白名单中的 `@` 宏调用。

~~~mil
while (running) {
    @unit.bind(Alpha);
    @unit.move(targetX, targetY);
}
~~~

- 用户不能定义宏、标签、原始 `@counter` 跳转、Memory 读写或保留字段写入；这些仍由编译器/runtime 独占。
- 每个宏由 target profile 提供签名、参数类型、权限、可能的暂停/控制副作用、临时槽需求和最低版本。普通处理器调用 worldOnly 宏是构建错误，不留给游戏解析器替换为 InvalidStatement。
- 宏展开通过内部 `SymbolId` 分配临时变量、标签和物理槽，而不是用用户可猜测的文本前缀。用户变量也会在链接时按模块符号重新命名，因此两个包、两个宏展开和用户源码不会发生捕获。
- 宏只接收显式的实参符号；它不能通过字符串拼接捕获调用方变量，也不能声明跨展开可见的全局名称。
- 展开结果保留“调用点 → 宏节点 → mlog 指令”的来源链。若超过 token、标签、指令或资源预算，诊断首先指向 MIL 宏调用点，并附带展开后的成本。

MPL 自动生成的 MIL 与用户 `.mil` 必须经过同一 profile 校验、资源链接器和最终 mlog 限制校验。性能敏感用户可以绕过高层 runtime，但不能绕过权限、硬件契约、flag 保留规则或内存预算。
