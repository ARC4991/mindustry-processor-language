# 宏中间语言设计（讨论稿）

> 状态：分层职责与 `.mil` 扩展名已确认；正式名称、宏定义语法与完整基础宏表待确认。本文暂以 MIL（Macro Intermediate Language）称呼该语言。

## 定位

MIL 同时承担两个角色：

1. MPL 的编译产物：承接单位 runtime、字符串表和其他高级概念的降级结果；
2. 性能敏感用户可直接编写的专家语言：可绕过 MPL runtime，但仍保留结构化控制流。

MPL 不出现 @。@ 只属于 MIL，用于调用映射到游戏基础能力的宏。

## 两阶段编译

~~~text
MPL
  → 语义分析与高级概念降级
  → MIL（结构化控制流 + 基础游戏宏）
  → 宏展开、标签与地址解析
  → 原始 mlog 指令
~~~

用户直接编写 MIL 时，从第二行开始进入流程。编译器应提供分别输出 MIL 与 mlog 的调试选项，并保留来源映射，使宏展开错误能定位回 MPL 或 MIL 源码。

项目与包的 `src` 目录均可混合放置 `.mpl` 与 `.mil` 文件；它们进入同一个链接单元并共享类型、导出符号与全局资源预算。包也可用 `.mil` 实现其公开 API。每个项目/包仍各自拥有 `.mplh`：该文件只声明硬件和资源需求，不包含 MPL 或 MIL 业务代码。

## 共同的结构化核心

MPL 与 MIL 都支持变量、函数、if、while、for、break、continue 和 return。控制流不是用户手写地址，而由 MIL 编译器生成跳转；其实现可通过对 @counter 的写入完成间接跳转。

~~~text
while (running) {
    @unit.bind(@alpha);
    @unit.move(targetX, targetY);
}
~~~

上例是 MIL 示意：while 是结构化语言特性，@unit.bind 与 @unit.move 是基础游戏宏。具体宏名称和参数形式尚未冻结。

## 分层边界

| 能力 | MPL | MIL |
| --- | --- | --- |
| @ 宏 | 不允许 | 允许 |
| Unit.getAll类型() 与私有单位 runtime | 自动降级 | 用户自行选择是否实现 |
| String 与字符串表 | 自动降级 | 用户直接使用输出与跳转相关宏；字符串布局由链接器管理 |
| 结构化控制流与函数 | 支持 | 支持 |
| 游戏基础指令 | 高级 API 间接访问 | 通过 @ 宏直接访问 |

MIL 宏展开必须生成不会与用户变量冲突的内部标签、临时变量与内存槽位，并在诊断中保留宏调用位置。

物理/虚拟内存不向 MIL 暴露：用户不能声明 Memory、传递内存给包，或直接读写槽位。宏展开所需的临时变量和内部槽位由编译器从 `.mplh` 已声明的预算中自动分配；不足时是构建期错误。
