# V146 目标配置（讨论稿）

> 状态：MPL 支持的基线目标配置。本文以本地提供的 Mindustry v146 源码为依据；新增版本必须以独立 profile 加入，不得默默改变 v146 的编译结果。

## 范围

v146 构建使用：

```json
{
  "target": {
    "mindustry": "v146"
  }
}
```

MPL/MIL、标准库、硬件校验、内容类型表和生成的 mlog 均绑定此 profile。包也必须声明兼容的目标 profile；首次链接时拒绝混用不同目标版本的包。

## 已从源码确认的目标事实

| 项目 | v146 行为 | 源码依据 |
| --- | --- | --- |
| 程序结尾 | `@counter` 越过指令数组末尾后，下一次取指先重置为 0，再从第一条指令继续 | `core/src/mindustry/logic/LExecutor.java`，`runOnce()` |
| 编译器主循环 | MPL 不生成隐式 `while (true)`；顶层语句按源码顺序直接降级 | 基于上述执行器行为的 MPL 约定 |
| 指令额度 | Micro / Logic / Hyper Processor 分别为 2 / 8 / 25 IPT | `core/src/mindustry/content/Blocks.java` |
| 物理内存 | Memory Cell 为 64 槽；Memory Bank 为 512 槽 | `core/src/mindustry/content/Blocks.java`、`MemoryBlock.java` |
| 单位绑定 | 对可逻辑控制的己方单位类型，`ubind` 按该类型缓存中的游标循环选择下一单位；无候选时 `@unit = null` | `LExecutor.UnitBindI` |
| 绘图缓冲 | 单处理器 graphics buffer 最多 256 命令；flush 前 Display 现有命令数与新命令数之和必须严格小于 1024 | `LExecutor.DrawI`、`DrawFlushI` |
| 文本缓冲 | `printflush` 最多写入 400 字符，随后清空 print buffer | `LExecutor.PrintI`、`PrintFlushI` |

## 顶层执行语义

`main.mpl` 没有隐式入口函数，也没有由 MPL 新增的主循环。它就是一段顺序指令流：

```mpl
var count: Int = 0;
count += 1;
AlertBoard.print(count);
```

编译器仅按顺序生成初始化、赋值与输出指令。达到末尾后，v146 执行器自身会在下一次取指时回到第一条指令，因此这段初始化会在处理器自然回到开头后再次执行；若控制流永远不回到它，变量值则保持在处理器变量中。MPL 不把这种目标行为命名为“main 循环”，也不提供与目标不同的伪生命周期。

若未来需要停止或等待，应显式设计为高层 API：v146 的 `stop` 指令会让 `@counter` 回退到自身，`wait` 会反复执行自身直至等待时间满足。它们不应被误写成“程序正常结束”。

## profile 应负责的校验

- `memory physical(link: ..., size: ...)` 必须匹配被链接的 v146 Memory Cell（64）或 Memory Bank（512）及其容量；
- `Unit.getAll类型()`、`Building.getAll类型()`、senseable 属性、控制动作和内容常量由 v146 的内容/逻辑描述表生成；
- 编译报告必须根据目标 Processor 类型计算 IPT，并报告 MPL/MIL 展开后的指令数、单次绘图命令数与单次文本输出上限；
- 组合 Display 的展开必须让任一物理 Display 在 flush 时满足命令总数严格小于 1024；Message 自动 flush 不得假设超过 400 字符仍可完整显示。
