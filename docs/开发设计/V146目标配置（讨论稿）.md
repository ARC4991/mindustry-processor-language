# V146 目标配置（讨论稿）

> 状态：MPL 支持的基线目标配置。本文以本地提供的 Mindustry v146 源码为依据；新增版本必须以独立 profile 加入，不得默默改变 v146 的编译结果。

## 范围

v146 构建使用：

```json
{
  "target": {
    "mindustry": "v146"
  }
}
```

MPL/MIL、标准库、硬件校验、内容类型表和生成的 mlog 均绑定此 profile。包声明最低 profile 与能力；根项目 target 不满足该下限时链接失败，但同一包不因同时可在更高 profile 构建而被拒绝。

## 已从源码确认的目标事实

| 项目 | v146 行为 | 源码依据 |
| --- | --- | --- |
| 程序结尾 | `@counter` 越过指令数组末尾后，下一次取指先重置为 0，再从第一条指令继续 | `core/src/mindustry/logic/LExecutor.java`，`runOnce()` |
| 编译器主循环 | MPL 不生成隐式 `while (true)`；顶层语句按源码顺序直接降级 | 基于上述执行器行为的 MPL 约定 |
| 单片硬限制 | 每个处理器最多 1000 指令、500 标签、每行最多 16 token；解析器在第 1000 条后停止读取 | `LExecutor`、`LParser` |
| 指令额度与范围 | Micro / Logic / Hyper Processor 分别为 2 / 8 / 25 IPT、10 / 22 / 42 格链接半径；可累计至约 5 × IPT 的一次执行批次 | `LogicBlock.java`、`Blocks.java` |
| 物理内存 | Memory Cell 为 64 槽；Memory Bank 为 512 槽 | `core/src/mindustry/content/Blocks.java`、`MemoryBlock.java` |
| 多处理器通信 | 各处理器变量、`@counter`、`@unit`、链接和缓冲均独立；共同链接同一 Memory 后可读写同一 `double[]`，但没有锁、CAS 或原子读改写 | `LogicBlock`、`LExecutor.ReadI/WriteI`、`MemoryBlock` |
| 单位绑定 | 对可逻辑控制的己方单位类型，`ubind` 按该类型缓存中的游标循环选择下一单位；无候选时 `@unit = null` | `LExecutor.UnitBindI` |
| 绘图缓冲 | 单处理器 graphics buffer 最多 256 命令；flush 前 Display 现有命令数与新命令数之和必须严格小于 1024 | `LExecutor.DrawI`、`DrawFlushI` |
| 文本缓冲 | `printflush` 最多写入 400 字符，随后清空 print buffer | `LExecutor.PrintI`、`PrintFlushI` |

## 顶层执行语义

`main.mpl` 没有隐式入口函数，也没有由 MPL 新增的主循环。它就是一段顺序指令流：

```mpl
var count: Int = 0;
count += 1;
AlertBoard.print(count);
```

v146 执行器在程序计数器越过末尾时会在下一次取指回到第一条指令；但 MPL 后端会在每个程序末尾生成 `stop`，使处理器停在该指令而不触发自然回绕。持续逻辑必须由 MPL 源码显式写 `while`，不会出现隐式 main 循环。

若未来需要停止或等待，应显式设计为高层 API：v146 的 `stop` 指令会让 `@counter` 回退到自身，`wait` 会反复执行自身直至等待时间满足。它们不应被误写成“程序正常结束”。

多处理器部署中的 Worker 是编译器 runtime：它不能在空闲时用 `stop` 等待共享 Memory 消息，因为 `stop` 不会被其他处理器唤醒。Worker 必须显式轮询版本化邮箱；这不改变普通 `main.mpl` 默认运行一次的语义。

## profile 应负责的校验

- `memory physical(link: ..., size: ...)` 必须匹配被链接的 v146 Memory Cell（64）或 Memory Bank（512）及其容量；
- 多处理器时必须对每个 shard 单独验证指令、标签、token、IPT、链接范围和本地 Memory alias；共享 Bank 的同一性通过启动握手验证，不能假定不同处理器的 `memory1` 必然相同；
- `Unit.getAll类型()`、`Building.getAll类型()`、senseable 属性、控制动作和内容常量由 v146 的内容/逻辑描述表生成；
- 编译报告必须根据目标 Processor 类型计算 IPT，并报告 MPL/MIL 展开后的指令数、单次绘图命令数与单次文本输出上限；
- 组合 Display 的展开必须让任一物理 Display 在 flush 时满足命令总数严格小于 1024；Message 自动 flush 不得假设超过 400 字符仍可完整显示。

## 已接入与后续工作

内置 `v146.json` 现已接入当前编译器：处理器/Memory/限制、已实现 lowering 使用的 `set`、`op`、`jump`、`ubind`、`ucontrol`、`sensor`、`print`、`printflush`，以及 Dagger、Alpha、Duo、Message、Display、Memory Cell/Bank、Switch 和当前 MIL 宏契约均由 JSON 提供。编译器会用该表校验 Unit 纵切和 `.mplh` 的直接 `link(...)` 类型。

这不是完整的 v146 内容或指令枚举。下一步继续从源码提取全部 UnitType/Block、`LAccess` senseable 属性、`LUnitControl` 控制动作、radar/locate 参数和绘图命令表；Building 遍历与控制的 lowering 也须在该表完整后接入。提取产物必须满足《[Profile 与构建产物 Schema（讨论稿）](数据格式/Profile与构建产物Schema（讨论稿）.md)》中的 `目标配置.schema.json`，纳入编译器资源，而不是在 Java 代码中散写字符串。
