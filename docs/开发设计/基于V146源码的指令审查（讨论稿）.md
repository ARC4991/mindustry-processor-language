# 基于 V146 源码的指令审查（讨论稿）

> 审查来源：Mindustry v146 的 `core/src/mindustry/logic/LExecutor.java`、`LStatements.java` 与 `world/blocks/logic/LogicBlock.java`。本文记录源码事实及其对 MPL 规范的约束，不将 mlog 的静默失败直接暴露为 MPL 语义。

## 指令清单与分层

v146 注册的 Logic 语句可分为：

| mlog 类别 | v146 指令 | MPL 定位 |
| --- | --- | --- |
| 基础 | `set`、`op`、`jump`、`stop`、`wait`、`end`、`noop` | 编译器 lowering；只有结构化控制流与未来 `wait` 进入 MPL |
| 内存/链接 | `read`、`write`、`getlink` | 不向 MPL/MIL 源码开放；由 `.mplh` 与内存布局器管理 |
| 输出 | `print`、`printflush`、`draw`、`drawflush`、`packcolor` | 由 Message / Display 面向对象 API 包装 |
| 建筑 | `control`、`radar`、`sensor`、`lookup` | 由 Building 对象和内容 API 包装，尚未冻结签名 |
| 单位 | `ubind`、`ucontrol`、`uradar`、`ulocate` | 由 UnitSet / Unit 对象 runtime 包装 |
| 世界/特权 | `getblock`、`setblock`、`spawn`、`status`、`spawnwave`、`setrule`、`message`、`cutscene`、`effect`、`explosion`、`setrate`、`fetch`、`sync`、`getflag`、`setflag`、`setprop` | 默认不进入普通 MPL；仅 profile 明确允许的受限管理 API 才可暴露 |

这与“高级 MPL 不出现 `@`、用户不能定义宏”的分层一致。MIL 可以在 profile 白名单内直接使用基础目标能力，但不能绕过资源、权限和保留字段检查。

## 执行模型：必须冻结的事实

### stop、end 与 wait

- `stop` 将 `@counter` 回退到自身，下一次取指仍执行同一条 `stop`，因此会真正停止后续程序。
- `end` 将 `@counter` 设为指令数；v146 下一次取指会将越界计数器重置为 0，所以 `end` 会重新开始程序，不能作为 MPL 默认终止方式。
- `wait t` 在同一条指令上自循环，内部以游戏 tick 累积 `Time.delta / 60`；它不是线程 sleep，也不是普通函数调用。

**MPL 规则：**每个程序末尾生成 `stop`。持续逻辑由用户显式的 `while` 表达；未来 `wait(seconds)` 只能作为可暂停语句实现，并必须在文档中标明“恢复到同一调用点”。不存在隐式主循环或 `state var` 生命周期。

### 指令预算与跨 tick

- Micro / Logic / Hyper 的基准 IPT 为 2 / 8 / 25。
- 一条 mlog 指令是唯一原子单位；一个 MPL 表达式、Message 输出、UnitSet 迭代步骤可能跨 tick。
- 处理器变量、跳转目标与指令对象状态会保留到下一 tick；不能把“源语句执行完”当作原子保证。

**待实现契约：**构建报告输出静态指令数、每个循环体的下界、可暂停 runtime 的私有状态槽位和配置处理器的 IPT。纯赋值在最后一个 `set` 前不得写入用户目标；复杂 runtime 必须显式维护可恢复阶段，不能依赖一次 tick 执行完毕。

## 目标层静默行为与 MPL 策略

| v146 源码行为 | 风险 | MPL 应采用的规则 |
| --- | --- | --- |
| `read` 越界返回 `0`；`write` 越界或无权限时忽略 | 数据错误没有诊断 | 禁止源码读写 Memory；`.mplh` + 静态布局在构建期检查容量 |
| `getlink` 越界返回 null | 链接顺序不稳定 | 不暴露动态索引；`.mplh` 只写 `link("message1")` 等游戏链接变量名，并提供部署检查 |
| `print` 文本缓冲到 400 UTF-16 字符后不再追加；`printflush` 总会清空缓冲 | 文本被静默截断或丢失 | String/Message runtime 记录最大长度；静态可知超限为错误，动态长度必须定义截断或分段策略 |
| 图形暂存缓冲最多 256 命令；目标 Display 现有命令加新命令必须严格小于 1024，否则整个 flush 丢弃 | 画面静默丢失 | Display 构建报告统计每帧命令；静态可知超限为错误，动态绘制 API 要有明确的预算/截断策略 |
| draw 数值用 10 位带符号打包 | 超范围坐标被截断 | Display API 规定可表示坐标为 `-1023..1023`；常量越界报错，动态值采用明确的 clamp 或 reject 策略 |
| `printflush` 目标不是己方 Message 时只清空缓冲 | 接线改变后输出消失 | `.mplh` 部署检查验证变量名、类型、队伍与权限；普通 MPL 不接受任意 Building 作为 Message |

## 硬件与链接

游戏在链接建立时按方块类型生成如 `message1`、`display1`、`memory1` 的 mlog 变量名。MPL 使用业务名绑定它：

```mpl
// 仅 hardware.mplh 允许。
const AlertBoard: Message = link("message1");
```

`link(...)` 不属于 MPL 表达式，也不以顺序或数组下标绑定硬件。后续 `mpl hardware check` 应读取目标部署信息并验证：链接变量存在、方块类型匹配、队伍/处理器权限满足、同一可写硬件的共享声明不冲突。

## Unit / Building API 的源码约束

- `ubind` 仅遍历己方且 `logicControllable` 的单位类型；无候选时当前 `@unit` 为 null。
- `ucontrol build` 受地图规则 `logicUnitBuild` 与单位能力共同限制。
- `control`、`sensor`、`radar` 等建筑操作要求目标是己方已链接建筑，除非是特权处理器。
- 世界指令在 `LStatements` 标记为 privileged，普通处理器不能把它们当作可移植能力。

**MPL 规则：**`Unit.getAllAlpha()` 返回惰性 `UnitSet<Alpha>`，`for` 取得非空借用 `Unit<Alpha>`；空集合只是不执行循环体。flag 是 runtime 保留属性，MPL/MIL 都不能读写。`Building.getAll...()` 应只从 `.mplh` 已声明或显式允许的链接集合构建，不能降级为任意 `getlink`。

## 仍需冻结的 API 细节

1. `wait` 是否进入第一版，以及它在函数、循环与 UnitSet 内的恢复限制；
2. `sensor` / `radar` / `control` / `ucontrol` 的强类型属性、枚举、权限与失败值；
3. Message 的动态字符串超长策略，以及 Display 动态命令的预算策略；
4. 特权世界 API 是否完全不进入 MPL，或以单独 `World` capability 包暴露；
5. 内容 lookup、packcolor、团队/内容/坐标等目标对象的类型与可空性；
6. v159.7 对每一条新增指令的兼容 lowering 与优化等价测试。
