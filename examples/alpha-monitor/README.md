# Alpha 受损单位监控

这是 MPL 当前讨论稿的端到端示例项目。它展示一个处理器如何：

- 由 `hardware.mplh` 集中声明屏幕、消息板、物理内存与虚拟内存；
- 不导入硬件常量，直接在 `main.mpl` 中使用屏幕、消息板等非内存资源；
- 自动汇总项目和外部包的内存需求，并只将屏幕等非内存硬件注入外部包；
- 遍历生命值低于阈值的 Alpha 单位、绘制柱状图并输出消息。

## 目录

```text
alpha-monitor/
├── mpl.json                         # 项目配置（讨论格式）
├── src/
│   ├── hardware.mplh                # 唯一硬件声明文件
│   └── main.mpl                     # 顶层入口
└── packages/status-panel/
    ├── mpl.json                     # 本地演示包元数据
    ├── hardware.mplh                # 包的资源需求
    └── src/index.mpl                # 包的公开实现（也可放置 .mil）
```

## 使用说明

当前仓库尚未提供编译器，因此此项目是语法和架构样例，不能直接构建。`mpl.json` 中的 `workspace:` 依赖写法用于表达“本地演示包”；正式包清单与锁文件格式仍待冻结。

构建时，`src/hardware.mplh` 是项目必需且唯一的硬件声明；每个外部包也必须拥有自己的 `hardware.mplh`。项目的 `export const` 非内存资源会自动对项目源码可见。物理/虚拟内存只作为全局预算存在，不会生成 `Data`、`Runtime` 等可读写变量；链接器会把项目和包的需求统一布局并校验容量。`StatusPanel` 的内存需求自动汇总，调用处只传入 `MainScreen`。

`src`（以及包的源码目录）可混合放置 `.mpl` 与 `.mil` 文件；本示例的业务实现使用 `.mpl`，需要极致性能的模块可改以 `.mil` 编写并进入同一链接单元。`.mplh` 始终只负责声明，不是任一种业务源码的替代品。
